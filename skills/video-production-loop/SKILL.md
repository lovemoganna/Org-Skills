# Video Production Loop

你是视频制作闭环的执行者。交付可播放的成片、可复现的工程和有边界的验证证据；计划或源代码不能替代成片。默认执行用户已经授权的本地制作，不把每个阶段都变成审批点。

人类读者可先读 [SOP 与调用方式](references/sop.md)，已运行的检查见 [验证记录](references/validation.md)。

## 路由与最小上下文

- 新建视频：先读 [制作与音频](references/production.md)；使用现有工程，或用 `scripts/bootstrap.py` 复制附带的 Remotion 起点。
- 复用本次认可风格：读 [已验证案例与预设](references/accepted-profile.md)。这是起点，不是固定画幅、题材、声音或时长限制。
- 批量生产、恢复任务：读 [批量与状态](references/batch.md)，使用 `assets/batch-plan.json` 和 `assets/run-record.json`。
- 验收或用户指出问题：读 [质量与反馈](references/quality-loop.md)。短改动只读相关条目，避免重新设计全片。

其他高级智能体可直接读取本文件及相对路径资源，不依赖 Codex 专有工具、绝对路径或某个账户。工具调用适配运行环境；文本请求不能替代实际工具执行。Skill 内脚本是辅助工具，不是自动导演。

## Loop 状态与完成门槛

`BRIEF → SPEC → ASSETS → PREVIEW → RENDER → VERIFY → DELIVER`

任何缺陷进入 `REVISE`，记录触发原因并回到最早受影响的阶段。外部依赖失败可进入 `BLOCKED`；取消进入 `CANCELLED`。这些是视频任务记录状态，不是宿主的 goal/automation 状态。

| 阶段 | 执行动作 | 可检查的完成条件 |
|---|---|---|
| BRIEF | 明确观众、核心观点、平台、画幅、语言、时长约束、可用素材、预算；缺省值写入记录 | 要表达什么、给谁看、何时算完成均已明确；只追问会实质阻塞制作的信息 |
| SPEC | 写 VideoSpec 与来源记录，设计场景节奏、标题、旁白和视觉证据 | 结构校验通过；关键事实有依据；图示与真实数据区分；总帧数满足硬时长 |
| ASSETS | 生成可试听的声音，准备字体、音乐与图像；测量真实音频长度 | 无缺失素材、截断语句、字体替换未说明；音频路径与配置一致 |
| PREVIEW | 打开可运行预览或渲染短样片；检查标题、布局、声音、切换 | 至少一个代表性场景可见；所用听审方式和未检查项已记录 |
| RENDER | 固定配置和依赖、生成 MP4 到独立修订目录 | 渲染进程成功，输出文件存在且非空；仅到此处才能说“已渲染” |
| VERIFY | 检测媒体规格、全片解码，检查实际成片抽帧和音轨 | 技术硬门槛通过；内容/视听缺陷已修复或透明列出；没有用指标冒充主观质量 |
| DELIVER | 给出新文件、预览、源码、证据和可复用命令 | 用户可以播放并复现；明确新旧版本；所报告路径存在 |

每轮记录 `issue → evidence → minimal_change → check → result`。不新增与反馈无关的修饰。通过门槛且没有新问题就交付，不为“更完美”无限迭代。

## 制作决策

1. **声音先于时间锁定。** 先合成再测量。总时长固定时优先精简文案、调整分段；时长可浮动时让镜头服从自然语句。用户要求提速时调整合成器语速，不默认拉伸已生成音频来硬塞镜头。
2. **确认用户不喜欢的具体层面。** “太慢”检查合成语速、句内停顿、段尾静音、切镜节奏；“反感”不能自动推导为永远禁用所有人声。可给短试听或采用合理且明确的初始方案，保留原版。
3. **对白是前景。** BGM 用实测电平与试听配平；音量倍率不是响度百分比。“高潮”可用能量分析找候选，但音乐结构需要听审，未听时如实说明。
4. **模板服务内容。** 选择解释关系的画面，不把所有题材都塞进固定五段。附带模板仅支持其声明的类型；新类型必须同步扩展校验、渲染与样片。
5. **画面只呈现有意的品牌。** 本预设无 Codex/Remotion 工具角标。用户品牌按要求保留；不要擅自移除素材已有的第三方标记。
6. **交付以证据为准。** HTTP 200、退出码 0、音轨存在都不足以证明内容或听感正确。记录技术验证和人工/模型视听检查的不同完成度。

## 执行与失败边界

- 先检查 Node、包管理器、FFmpeg/ffprobe、中文字体、渲染浏览器及网络。锁定一致的 Remotion 依赖，检查版本兼容；旧版本号是复现基线，不宣称是最新版本。
- 创建独立工作目录。复用用户既有工程时保留未涉及修改；新修订先写新文件，验收后才更新 `latest` 指针。
- 外部 TTS 的暂时性网络失败至多重试 2 次并退避；403、配额、凭据错误先诊断，不无限循环，不默默换成低质量声音。不得绕过访问控制。
- 默认为每个输出最多 3 轮有证据的自动质量修订。用户反馈可启动新一轮；持续同类失败要保留半成品和明确阻塞原因。执行预算以用户约束为先。
- 缺素材、接口不可用或不能听审时，尽量完成不依赖它的工作，准确报告完成度。用户要求的旁白失败不能以静音版冒充完成。
- 只使用用户授权的素材和服务。制作授权不等于付费、发布、发送他人或上传私密文件的授权。批量创建子任务不要求自动创建聊天或自动启动子智能体，服从宿主的委派规则。

## 输出最小集合

`final.mp4`、VideoSpec、可安装源码/依赖锁、资产来源与选择记录、渲染记录、`media-report.json`、实际成片抽帧、质量检查与遗留问题、运行命令。批量另附逐项状态清单，不只给一个“全部完成”。

使用 `scripts/verify_media.py` 检查 MP4；参数见 `--help`。脚本通过仅证明其列出的技术检查。最终回复应短：交付链接、关键变更、验证结果、真实限制。若有待用户选择的声音，提供可播放试听，而不是只罗列音色名。
