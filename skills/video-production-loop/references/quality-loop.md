# 质量检查与反馈修订

## 硬门槛：可执行检查

- VideoSpec 合法，资源存在；旧缓存的文本/音色/时长与本次 spec 一致。
- 实际 MP4 的宽高、帧率、时长、解码帧数与 spec 一致；容差不得掩盖缺帧。
- 完整解码成功；有声需求存在音轨并且有有效非静音信号。
- 无尾音截断、渲染错误画面、缺字或溢出、遗漏的用户修改。
- 输出版本、来源及质量记录齐备；交付文件必须是本轮验证的同一文件。

`verify_media.py` 检测前几项技术条件并从视频抽帧。音量峰值只检查采样峰值，不等于 true peak；存在有效音轨也不能证明台词正确。

## 视听检查：明确谁检查了什么

检查实际 MP4 的开头、每段中间、场景边界前后与结尾，短片应尽量完整播放。重要标题和字幕逐段检查。转换后的文件也要再检查，不能只看原始预览。

| 维度 | 要回答的问题 | 证据 |
|---|---|---|
| 内容 | 核心观点准确吗？画面、旁白、字幕是否一致？ | 来源与逐段核对 |
| 声音 | 语速、停顿、发音自然吗？句尾是否完整？ | 实际试听主体/区间；未听写明 |
| 混音 | 正常音量下能否轻松听清对白？音乐是否抢前景？ | 试听 + 电平检测 |
| 画面 | 信息层级清楚、中文正常、边距充分吗？ | 抽帧与预览 |
| 节奏 | 信息读得完吗？是否因填满固定时长而长时间无意义停留？ | 时间线 + 完整播放 |
| 符合要求 | 指定素材、品牌、角标和修改是否正确？ | 对照本轮需求逐项验收 |

每项标 `pass / fail / not_checked` 并给依据；不要制造“质量 98 分”而不解释量表。完成技术验证但未听审可以交付，并透明说明限制，不冒充完整视听验收。

## 缺陷到动作

| 反馈 | 先定位 | 最小动作 |
|---|---|---|
| 声音太慢 | 合成速率、逗号停顿、段尾静音 | 小幅提高语速、合并零碎短句、调整段落；重测时长 |
| 声音生硬 | 音色、引擎、后期加速、句法 | 同稿短试听，换神经音色或改写，不立即删除所有对白 |
| BGM 抢戏 | 原音乐响度、人声频段、说话段电平 | 降低/duck/换段，重新测混音 |
| 太空/太挤 | 阅读负担、画面停留、视觉证据 | 调整具体段布局与节奏，不全片换皮 |
| 移除角标 | 角标来源与具体范围 | 修改对应层；抽帧检查，不删除用户品牌 |
| 渲染失败 | 日志、浏览器、字体、资源、内存 | 最小复现；修复失败原因，不用旧片冒充新片 |

修订后只对受影响资产重新生成，但最终输出必须完整解码。变了声音也要重查镜头对齐；变了文字也要重查版面；变了模板要验证同模板的所有批量任务。

## 退出

没有已知实质问题且验收达到约定范围，交付。达到自动修订上限仍有缺陷，写出剩余问题与需要的下一步。用户的新反馈作为新的明确目标处理，不将上一轮意见固化成永久偏好。
