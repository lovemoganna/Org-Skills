# 制作与音频

## 先确定可调整量

将要求分为硬约束和可调整量。硬约束例如发布平台画幅、确切总时长、必须使用的素材；可调整量例如场景数、句长、字体大小、语速和音乐区间。不要默认“30 秒、五段各 6 秒”适合每个视频。

为每个场景记录一句信息目标、视觉表达、旁白、预计长度。字幕摘要可以不同于逐字旁白，但不能表达相反意思。知识性结论要记录来源；类比曲线标注“概念示意”，不能伪造统计数据。保存事实来源与素材来源为不同字段。

## 配音

1. 根据语言、风格、网络与预算选择 TTS。可用的默认候选是 Edge 在线神经声音；Windows 本地旧 SAPI 声音是另一类质量，不可当作等价替换。
2. 中文首轮可生成同稿 10–15 秒试听：云希与晓晓。已有用户认可的音色时直接复用，不反复要求选择。
3. “对白”若明确多角色，给每个 speaker_id 固定声音并记录台词与时间；无人物设定的知识解说可先理解为旁白，不擅自添加虚构人物。
4. 简洁口语、自然衔接，少堆顿号和短逗号。测量语音的有效开始、结束与句间间隙，而非只看文件长度。附带脚本测文件时长，必要时另外用 FFmpeg silencedetect 看实际静音；不能据此自动切掉轻声尾音。
5. 这次认可的候选为云希 `+10%`，但不同句子/语言要重新试听。调语速优先由合成器完成；更快不一定更流畅。
6. 合成完成后验证文件非空、可解码、持续时间、无句尾截断。长度超出镜头时修改稿件或时长，再重新生成。缓存键至少包含文本、voice、rate、pitch、引擎版本；改稿不可复用旧音频。
7. 环境不能听音频时交付试听并标记“未听审”，不得写“发音自然/情绪准确已确认”。

`edge-tts` 的 CLI/Python 可生成 MP3 与字幕，服务联网且不是微软正式承诺的第三方 API。正式 Azure Speech 是另一条需账户/凭据/配额的路线。部署时查阅上游最新说明与限制，不把旧价格和接口可用性写死。

## BGM

- 优先用户给定文件；记录原文件名、可选哈希、起止秒、选段方法。
- 对长音频可按 1 秒分块计算 RMS，再比较目标长度窗口。最高能量只是候选，可能是循环段、噪声或已经限幅的段落；能试听时还应检查旋律发展、乐句起止、突兀切口。
- 有对白时以音乐平均电平低约 16–22 dB 作为起始范围；同一分析方法下测量后再听。RMS 与 LUFS 不同；报告使用哪一种，不能互换。
- 如原始语音过小，先将对白调到可用响度并检查峰值，再配平音乐。单纯把 BGM 压低不能解决前景本身过小。
- 混音前保留余量；默认温和淡入淡出，必要时在说话期间压低音乐。音乐含演唱或强烈中频时更可能遮蔽对白，需要降低或换段。
- 导出后测混音峰值/响度，检查旁白确实写入、音乐未被遗漏。可将解码输出与预计混音做相关性比较，证明信号路径；相关性高不证明悦耳。

## 画面与 Remotion

使用帧号驱动动画；避免依赖当前时间、无种子的随机数和运行时远端素材。先将资源准备到本地 public 目录，确认中文字体、文件大小写及路径跨平台可用。

标题留足边距；长文本以改写/换行为先，避免无限缩小字体。验证实际输出像素尺寸，不只看浏览器缩放预览。竖屏需要重新排版，不能将横屏非等比压缩当作适配。

场景组件与 VideoSpec 校验是一个契约：类型、items 数量、尺寸、时长、资源路径变更必须一致。动态时长由整数帧计算，避免累计舍入误差。固定总帧数时，明确最后一段吸收余数的规则。

## 附带起点的真实范围

`assets/remotion-starter` 来自本次已验收工程，保留 hook / equation / comparison / steps / takeaway 五类组件与相同依赖锁。默认示例无音频、无 BGM，仅用于首次烟雾渲染；包内不包含用户歌曲、系统字体、私人路径或生成历史。

复制后执行 `npm ci`、`npm run validate`、`npm run preview`、`npm run render`、`npm run verify`。首次渲染可能下载浏览器。辅助脚本使用 Python 3.11+，媒体验收需要 ffmpeg/ffprobe 在 PATH 中；新环境先运行各工具的版本检查。需要旁白时，激活自己的 Python 虚拟环境，安装 `edge-tts==7.3.1`，设置 narrationEnabled=true，执行 `npm run audio`。其他 TTS 引擎也可将结果写到 spec 指定路径。

该起点是 16:9 起点，不是任意画幅引擎。换画幅、增加动画模板、品牌或角色时进行真实样片验证。
