# LLM Wiki Maintainer

## 目的与边界

将新材料融入既有知识网络，而不是不断生成孤立摘要。唯一事实源为用户指定的 Org 仓库；默认目标为 `lovemoganna/org-notes` 的 `main`。发布器是 `org-museum.el`，不修改其渲染引擎。不要求改用 Markdown、向量数据库、Obsidian 或新增服务器。

本 Skill 是知识维护的编排层，不替代 `note-reforge` 的单篇内容加工，不替代 `org-museum-ingest` 的公开仓库收录和发布，也不替代 `loop-engineering-meta` 的故障诊断。执行时先读取仓库的真实版本和已部署的存储约定，缺少必要文件或权限时输出阻塞与候选变更，不宣称执行成功。

## 入口

- `用 llm-wiki-maintainer 维护知识库：<来源 URL / 文件 / 主题>`：摄入并维护。
- `用 llm-wiki-maintainer 回答：<问题>`：索引优先问答，默认只读；不自动保存。
- `用 llm-wiki-maintainer 检查知识库：<范围>`：健康审计，默认只读；修复须明确授权。
- `用 llm-wiki-maintainer 整合：<主题或来源集>`：分析跨页面更新建议，明确写入授权后提交。

用户明确要求“发布/更新到网站”时，可提交已经验证的变更；仅要求分析或回答不得写入。用户允许收录不等于允许改写所有相关旧页面；不确定或涉及不同作者判断时先保留候选差异并说明。

## 操作契约

1. **发现**：读取仓库默认分支、`museum.json`、现有笔记和索引；确认真实扫描目录、相对路径约定、页面身份字段及发布工作流。未确认时不得自行假定根目录或公开 URL。
2. **原始证据**：来源只读。外部 URL 保留原链接、标题、作者（已知时）、读取时间及精确片段/位置；原文未留存时不得声称拥有永久副本。不得把非公开、含密钥或敏感个人信息的原文放入公开 `org-notes`。如需保存原文，使用事先确认的非公开只读来源区。
3. **检索**：从既有索引、文件路径、标题及 Org `file:` / `id:` 关系发现相关页面，必要时阅读原始证据。站点生成的 `index.html` 与 `.org-museum-index.json` 是导出产物，不视为可人工修改的真源。
4. **建模**：按 Source（来源）、Entity（实体）、Concept（概念）、Synthesis（综合）识别节点；仅建立证据支持的关系。区分引用、相关、依赖、因果、冲突，禁止从共同出现推断因果。已有页面优先更新，只有确实没有对应主题才新建。
5. **证据判定**：每项新增/变更结论记录 source、locator、时间（可得时）、状态（已验证/来源声称/推断/待核实）、适用条件。相反陈述先区分事实矛盾、时间版本、环境或定义差异；未解决时并列保存，不静默覆盖旧说法。AI 增加但未经项目核实的解释沿用 `note-reforge` 的 `〔补〕` 规则。
5a. **动态来源版本检查**：如果已有 Wiki 页面引用的是会变化的代码、Skill、规则或官方文档，先固定当前可访问的 revision/Commit 与检查日期，并读取目标文件的最新版本及相关变更提交；不要仅因仓库 HEAD 变化就判定某个结论失效。将旧 Claim 的适用版本/日期与新证据比对，按以下顺序裁决：① 同一对象同一时点同一条件且命题互斥，记事实冲突并列双方；② 不同日期、版本、环境、范围或词义导致的差异，记版本漂移或条件差异；③ 没有足够定位信息，记待核实。对于真实漂移，保留历史原文，追加带日期、旧新来源定位、现行调用方式及失效边界的说明；不得悄悄改写历史任务、测试答案或旧命令。来源仓库为私有时，只可在获授权的范围内使用，不能把私有全文复制到公开 Wiki。事件键至少包括来源对象、变更 Commit 和主题，重复执行必须无新增变更。对未变化的事实或命令保持原样，禁止为了体现“更新”强行制造差异。
5b. **同期争议与后续裁决**：来源对同一事件持相反立场，不自动构成严格事实互斥。必须核对对象、时间窗口、业务产品、全称/存在量词与来源所主张的命题，逐项检验是否可以同时成立；“有阻断措施”和“有人绕过措施”可以同时为真。为每条重要 Claim 标记 `ALLEGATION`（未裁定指控）、`PARTY_STATEMENT`（当事方声明）、`ADJUDICATED_FINDING`（裁决在明确范围内的事实认定）或 `UNKNOWN`（缺证据），保留原始日期、URL 和段落定位。后续裁决只能更新其覆盖的具体 Claim，不能使所有起诉内容自动转为已证实，也不能删除当时的反驳。证据未构成严格 P/非 P 时，标记为“同期立场分歧”，不得声称严格同条件矛盾回归通过。
6. **拟议变更**：先生成受影响文件清单与最小 diff（新页、旧页、链接、索引、日志）；保留所有已存在的 `#+WIKI_ID`、`#+INGEST_ID`、`#+WIKI_STATUS`、`CUSTOM_ID`、来源、代码块、路径和外链。禁止产生同身份 `.next.org` 进入发布扫描目录。
7. **提交门禁**：运行 `references/verification.md`。测试失败不提交；用户只授权单页更新时不得越权改写其他页面。批量修改应以基线 SHA、最小提交、非强推方式写回；竞争修改时重读并重新计算差异，不覆盖对方提交。**跨页面 Wiki 链接门禁**：目标 WIKI_ID 存在只能证明源引用基本合法，不证明导出 HTML 中的链接可到达。对于当前 `org-notes` 发布器，默认使用已验证的 `[[wiki:WIKI_ID][标题]]`；`wiki:WIKI_ID#fragment` 等含章节锚点写法须先取得当前导出器的真实 HTML 可达性证据，否则不得写入发布源。提交后必须以发布流水线的 HTML 链接验证作为最终门禁；失败则定位第一条链接并做最小修复后重跑，不可只看源级校验通过。
7a. **持续集成门禁（2026-10-12 已有实现）**：目标 `lovemoganna/org-notes` 的 `.github/workflows/publish.yml` 已在发布前执行 `tools/test_wiki_integrity.py`（一次性临时 Git 仓库验证重复摄入不新增提交、并发写入的非快进拒绝、断链/身份/索引/日志反例），随后执行 `tools/check_wiki_integrity.py`（只读扫描真实 Org 源目录），再执行原始发布器结构检查和 HTML 构建。以 GitHub Actions 的实际步骤与部署回执判定结果，不能只因本地测试通过就称网站已发布。这些自动门禁验证的是确定性约束，不能证明一手证据真实性、实际语义正确或真实 T17 互斥成立；用户资料、密钥和敏感内容仍需独立审查。发布器原有验证保留，不以新脚本替代。
8. **索引与日志**：维护人工可读的 Org 知识索引页和追加式 Org 维护日志页（逻辑角色分别对应 `index.org` 和 `log.org`）。**文件路径必须服从目标仓库实际发布契约**，不得硬编码裸文件名。对 `org-notes` 使用 `notes/<kind>/<topic>/<WIKI_ID>.org`，并保留所有必需文件头；已有索引 ID 为 `a4b7cf91-5db8-4a2f-90e2-89f3ea14bcd5`，已有日志 ID 为 `71e02e9d-80ff-4a75-a7aa-092532c14fd0`，应先核验其实际存在与身份一致再更新，禁止重复创建。索引覆盖当前可用页面（链接、简述、类别），日志按事件标识追加且重复执行不重复记账。查询只读时只提供日志候选，不为记日志破坏只读约束。
9. **发布验证**：需要发布时调用或遵守 `plugins/org-museum/skills/org-museum-ingest` 的最新 GitHub/发布契约；核验实际提交和构建回执。不能将“提交成功”“部署成功”“页面可访问”混为一谈。

## 四种工作模式

### Ingest：增加来源并更新旧知识
检索候选旧页 → 建立证据表 → 标出受影响的 Source/Entity/Concept/Synthesis → 差异与冲突分析 → 最小修改 → 验证 → 按授权提交 → 更新索引/日志 → 发布回执。材料是旧笔记时可调用最新版 `note-reforge`，但其默认 `.next` 输出不能直接进入站点扫描目录。

### Answer：基于现有 Wiki 回答
从已核实的知识索引 Org 页面（或原有入口）开始 → 打开相关 Org 页 → 对重要结论复查来源 → 回答并分别标明已验证、来源声称、推断或材料不足。发现有价值的新比较或综合时，**建议**保存，未经授权不落库。无来源时明确缺口，不补造引文。

### Audit：知识库健康检查
检查链接失效、孤儿页、重复实体、缺少来源定位、事实过期、内容矛盾、索引遗漏、身份冲突、发布扫描目录内的临时草稿。报告每一项：文件/结论、证据、风险、是否可凭现有材料修复、下一步动作。无法读取全仓时说明覆盖范围，不宣称全站通过。

### Synthesize：跨源综合
围绕一个问题汇总各页和原始证据，分离一致、冲突、未解决的事实；仅在确有跨源增量时提出综合页；已有综合页优先增量更新。每条新关系提供源位置，保留不同视角的限定。

## 验收与停止条件

参照 `references/verification.md` 的门禁及回归样例。至少覆盖：重复摄入幂等、仅新来源更新旧页、矛盾并存、无证据不补写、断链发现、只读问答不写、发布身份安全、受保护原文不泄露、并发版本冲突。出现无法核实的原始资料、身份冲突、未授权跨页修改、公开隐私泄露或回归失败时停止写入，保留失败原因与可复现下一步。

## 结果输出

交付影响文件与 diff 摘要、证据及冲突状态、验证结果、真实 Commit/发布状态和剩余风险。只做检查或问答时说明“未修改仓库”。不能接入工具时返回可执行的候选补丁，不假称已保存。
