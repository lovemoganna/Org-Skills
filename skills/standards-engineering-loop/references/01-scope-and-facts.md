# 通用标准规范撰写与 Loop 自迭代优化元提示体 V3

## 一、任务定位

你的任务不是润色材料、机械填表或堆砌专业概念。

你需要把零散、模糊、口语化或互相冲突的要求，还原为一套：

* 对象清楚；
* 条件可判断；
* 动作可执行；
* 结果可验收；
* 边界可解释；
* 依据可追溯；
* 版本可管理；
* 出现新情况后可继续修订；

的标准规范。

核心闭环：

```text
识别领域
→ 映射对象
→ 还原事实
→ 建立标准
→ 组合规则
→ 设计测试
→ 核验依据
→ 保存基线
→ Loop 质检
→ 最小修正
→ 回归验证
→ 发布与持续复核
```

# 三、输入

【需要制定标准的领域、问题或任务】

【该规范要解决什么问题，将影响什么行为、判断或决策】

## 3. 规范对象

【人、内容、数据、流程、行为、系统、技术、能力、风险、产品等】

## 4. 使用者

【谁负责阅读、执行、审核、验收或维护】

## 5. 使用场景

【在什么业务、地区、环境、阶段或条件下使用】

## 6. 已知事实与要求

【会议记录、现有 SOP、业务规则、历史材料、示例、经验等】

## 7. 已有分类或结构

【标签体系、流程阶段、能力等级、数据结构、技术架构等】

## 8. 已知样本或案例

【正例、反例、边界案例、故障案例、争议案例、历史误判等】

## 9. 依据来源

【法律法规、监管规则、官方文档、内部制度、行业惯例、实验结果等】

## 10. 输出载体

【一张大表、SOP、规则库、检查清单、技术规范、课程标准等】

## 11. 现有限制

【成本、时间、资源、权限、系统能力、技术条件、风险容忍度等】

【例如：必须渐进、使用 Lisp 表达式、短小精悍、只能一张主表等】

# 四、不可违反的原则

## 1. 事实、判断、动作和未知必须分开

所有内容必须归入以下四层之一。

### 事实

可以观察、测量、查询、回放或提供证据的内容。

### 规则判断

根据事实、阈值、关系和排除条件推导出的结论。

### 执行或处置动作

根据判断结果、场景和治理策略采取的行为。

### 未知或待裁决

信息不足、规则冲突、依据失效或场景未覆盖。

不得为了填满模板而强行判断。

---

## 2. 标准不等于目标口号

以下表达不能直接作为标准：

* 提升质量；
* 保证安全；
* 熟悉功能；
* 注意风险；
* 适当优化；
* 视情况处理；
* 尽量避免；
* 提高效率；
* 确保稳定；
* 掌握高级能力。

必须拆成：

```text
观察对象
+ 适用条件
+ 具体动作
+ 验收证据
+ 排除条件
```

---

## 3. 不得编造事实和参数

禁止编造：

* 法律条款；
* 官方规则；
* 技术限制；
* 产品功能；
* 性能阈值；
* 准确率指标；
* 责任人；
* 生效日期；
* 费率、价格或配额；
* 当前版本状态。

无法确认时标记为：

```text
【待业务确认】
【待技术确认】
【待法务确认】
【待数据测算】
【待样本验证】
【待官方依据复核】
```

---

## 4. 示例不自动等于规则

示例只能用于解释、验证或发现边界。

不得因为某个案例存在，就直接将案例中的所有特征升级为普遍规则。

---

## 5. 分享而不是考试

直接说明：

* 概念；
* 条件；
* 判断；
* 边界；
* 结论；
* 执行方法。

不得通过提问、练习题或“先让读者自己思考”推动正文。

---

## 6. 最小必要复杂度

只引入解决当前问题所必需的结构。

不得为了显得完整而增加：

* 无实际用途的层级；
* 重复字段；
* 预防性架构；
* 无法验收的指标；
* 尚未出现需求的规则；
* 不能解释作用的专业概念。

---

# 五、阶段一：识别标准类型

不得直接开始写正文。

先判断本次任务属于哪类标准。

| 标准类型   | 主要解决的问题      | 典型结果        |
| ------ | ------------ | ----------- |
| 分类标准   | 一个对象属于什么     | 标签、类型、等级    |
| 判定标准   | 在什么条件下成立     | 命中、不命中、待裁决  |
| 操作标准   | 一件事应如何执行     | 步骤、角色、输入输出  |
| 准入标准   | 满足什么条件才能进入   | 门槛、阻断项      |
| 能力标准   | 能力如何逐级提升     | 阶段、等级、升级条件  |
| 技术使用标准 | 某项技术何时以及如何使用 | 场景、规范、反模式   |
| 质量标准   | 什么结果才算合格     | 指标、阈值、验收方法  |
| 风险治理标准 | 风险如何识别和处置    | 等级、措施、升级路径  |
| 数据标准   | 数据如何定义、产生和使用 | 字段、类型、质量、血缘 |
| 流程标准   | 工作如何在状态间流转   | 节点、责任、输入输出  |
| 混合标准   | 同时包含多种标准     | 分层组合结构      |

输出：

```text
主标准类型：
辅助标准类型：
判断依据：
```

若属于混合标准，必须先拆成多个层次，不得把分类、流程、能力和处置混在同一层。

完成标准类型识别后，将通用概念映射到当前领域。

| 通用概念   | 当前领域对应对象 | 定义或示例 |
| ------ | -------- | ----- |
| 规范对象   | 【填写】     |       |
| 标准单元   | 【填写】     |       |
| 原子条件   | 【填写】     |       |
| 组合规则   | 【填写】     |       |
| 正例     | 【填写】     |       |
| 反例     | 【填写】     |       |
| 边界例    | 【填写】     |       |
| 排除例    | 【填写】     |       |
| 验收证据   | 【填写】     |       |
| 后续动作   | 【填写】     |       |
| 生命周期状态 | 【填写】     |       |

不同领域示例：

| 通用概念 | 内容标注    | 技术使用规范     | 能力成长规范    |
| ---- | ------- | ---------- | --------- |
| 标准单元 | 风险标签    | 使用规则       | 阶段标准      |

禁止在映射完成前直接套用其他领域术语。

# 七、阶段三：确定组织轴

一张主表只能有一个主要组织轴。

可选组织轴：

* 按对象分类；
* 按风险等级；
* 按业务流程；
* 按能力阶段；
* 按数据生命周期；
* 按技术复杂度；
* 按责任角色；
* 按使用场景；
* 按时间顺序；
* 按优先级。

输出：

```text
主要组织轴：
辅助组织轴：
选择原因：
```

约束：

* 同一层级不得混合多个分类维度；
* 每条标准只能有一个主要归属；
* 公共规则应通过引用复用，不得重复抄写；
* 渐进型规范必须说明升级依据；
* 分类型规范必须说明上下级关系；
* 流程型规范必须说明前置和后置状态；
* 并列能力不得伪装成递进阶段。

# 八、阶段四：还原事实与依据

先将输入材料拆为：

| 类型    | 内容                  |
| ----- | ------------------- |
| 已确认事实 | 有材料或可靠来源支持          |
| 明确要求  | 已明确需要新增、修改、停止或限制的内容 |
| 合理推导  | 根据事实进行的逻辑推导         |
| 设计决策  | 为使标准可执行而选择的结构       |
| 示例    | 用于说明或测试的案例          |
| 冲突信息  | 不同材料之间互相矛盾          |
| 缺失信息  | 无法根据现有材料确定          |
| 待确认项  | 需要特定角色作出决定          |

不得把：

* 推导写成事实；
* 设计决策写成官方要求；
* 示例写成通用规则；
* 临时口头要求写成长期制度。
