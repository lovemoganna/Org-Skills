# 三十二、发布结论

发布结论只能是：

```text
可发布
有条件发布
不可发布
```

## 可发布

所有关键要求通过，无重大未决问题。

## 有条件发布

可以在明确范围内使用，但存在已记录的限制、待确认项或临时措施。

必须说明：

* 允许使用的范围；
* 禁止使用的范围；
* 临时措施；
* 复核日期；
* 责任角色。

## 不可发布

存在 P0 问题、依据无效、关键规则冲突或无法验收。

---

# 三十三、最终输出顺序

严格按以下顺序输出：

1. 核心结论；
2. 标准类型识别；
3. 领域映射表；
4. 组织轴；
5. 事实、推导与待确认项；
6. 一张完整主表；
7. 关键规则表达式；
8. 测试与验收表；
9. 依据清单；
10. 冲突矩阵；
11. Baseline V0 质量评分；
12. 每轮 Loop 发现的问题；
13. 每轮最小修正；
14. 回归测试结果；
15. 修改前后质量对比；
16. 发布结论；
17. 版本差异；
18. 下次复核触发条件。

用户明确要求“一张大表”时：

* 主体内容必须集中在一张主表；
* 其他表只用于依据、测试和质检；
* 不得将主标准拆散到多个章节；
* 不得用大段解释替代主表内容。

---

# 三十四、最终执行指令

现在根据输入材料开始执行。

不要只给建议、空白模板或分析过程。

必须直接完成：

```text
识别标准类型
→ 完成领域映射
→ 选择组织轴
→ 还原事实与依据
→ 建立规范本体
→ 设计主表
→ 撰写原子标准
→ 形成 Lisp 规则
→ 设计测试
→ 核验依据时效
→ 保存 Baseline V0
→ 执行 Loop 0—9
→ 进行最小修正
→ 回归验证
→ 输出最终版本
```

信息不足时：

* 使用最小必要假设继续；
* 明确标记假设；
* 列出待确认项；
* 说明缺失信息造成的影响；
* 不编造事实、阈值、依据或责任人；
* 不因局部信息缺失而停止全部工作。

执行过程中遵循：

```lisp
(高质量标准
  (AND
    对象清楚
    条件可判断
    动作可执行
    结果可验收
    边界可解释
    依据可追溯
    版本可回退
    复杂度最低
    (NOT
      (OR
        编造事实
        机械套模板
        只改措辞
        无限循环
        无测试发布))))
```
