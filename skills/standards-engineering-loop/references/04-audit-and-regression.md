# 十九、Loop 0：领域适配质检

检查：

* 是否识别了正确的标准类型；
* 是否完成领域映射；
* 是否残留其他领域的术语；
* 是否选择了正确的组织轴；
* 是否符合用户指定的输出载体；
* 是否把分类、流程、能力、处置混在同一层；
* 是否存在伪递进结构。

领域适配失败时，必须先修正框架，不得继续润色具体条文。

---

# 二十、Loop 1：依据时效质检

检查：

* 是否存在更新版本；
* 原依据是否被替代或废止；
* 是否属于官方当前文档；
* 规则是否只适用于特定版本；
* 来源是否真的支持当前结论；
* 是否出现新的例外或替代方案；
* 不同官方依据是否冲突；
* 最后核验日期是否真实；
* 是否设置失效触发条件；
* 是否明确复核责任人。

以下问题属于发布阻断：

* 关键标准仅依赖过时来源；
* 依据当前状态无法确认；
* 官方来源互相冲突且未解决；
* 使用版本与依据版本不一致；
* 引用内容不能支持结论；
* 依据变化后未运行回归测试。

---

# 二十一、Loop 2：完整性质检

检查是否缺少：

* 规范对象；
* 适用范围；
* 使用者；
* 责任角色；
* 原子条件；
* 执行动作；
* 排除条件；
* 验收证据；
* 依据；
* 状态；
* 版本；
* 失效条件；
* 升级或退出条件；
* 异常和未知处理。

无法补齐时列入待确认项，不得编造。

---

# 二十二、Loop 3：原子性质检

逐条检查：

* 一行是否只表达一条主要标准；
* 是否同时混入多个动作；
* 条件是否仍能继续拆分；
* 是否存在循环定义；
* 是否只有结论没有证据；
* 是否只有原则没有动作；
* 是否把目标写成标准；
* 是否把处置写进事实；
* 是否把标签写成特征。

发现问题后，拆分为可独立编号、测试和维护的标准。

---

# 二十三、Loop 4：边界与冲突质检

检查：

* 两条标准是否重复；
* 是否互相矛盾；
* MUST 与 SHOULD 是否冲突；
* GATE 是否缺少必要条件；
* 排除条件是否让规则永远无法成立；
* 是否存在循环依赖；
* 是否有规则几乎永远命中；
* 是否有规则永远不触发；
* 多条标准同时成立时如何处理；
* 新场景是否进入未知或升级流程。

输出冲突矩阵：

| 标准A | 标准B | 是否可同时成立 | 冲突类型 | 原因 | 处理规则 |
| --- | --- | ------- | ---- | -- | ---- |

---

# 二十四、Loop 5：反事实质检

对每条关键标准依次测试：

* 删除一个必要条件，结果是否改变；
* 增加一个排除条件，结果是否改变；
* 将 MUST 改成 SHOULD，会造成什么风险；
* 不执行本条，如何发现；
* 提前进入下一阶段，会发生什么；
* 不升级是否仍能满足需求；
* 换到其他场景是否仍然成立；
* 阈值略低或略高时如何判断；
* 依据版本变化后是否仍然成立。

如果条件变化但结论始终不变，该条件可能无效。

如果任何轻微变化都改变结论，规则可能过度敏感。

---

# 二十五、Loop 6：可执行与可验收质检

分别从以下角色检查。

## 执行人员

是否能直接知道要做什么。

## QA

是否能直接编写测试和判定通过。

## 负责人

是否能判断是否发布、暂停或回滚。

## 产品与研发

是否能映射为字段、状态、接口或系统逻辑。

## 新成员

是否能在不依赖口头解释的情况下执行。

## 法务、合规或安全

是否能找到依据、适用范围和责任边界。

仍需猜测的内容必须继续拆解。

---

# 二十六、Loop 7：证据与可追溯性质检

检查：

* 每条关键事实是否有来源；
* 推导是否明确标记；
* 测试数据是否可追溯；
* 标准是否关联测试；
* 修改是否记录原因；
* 验收是否保留证据；
* 依据版本是否明确；
* 标准与旧版本关系是否明确；
* 责任角色是否真实存在；
* 临时规则是否有到期条件。

---

# 二十七、Loop 8：复杂度压缩

检查：

* 是否存在同义重复；
* 是否有不必要字段；
* 是否重复描述公共条件；
* 是否可以复用已有原子条件；
* 是否存在伪递进阶段；
* 是否为低频情况设计过重结构；
* 是否存在纯知识介绍而非标准；
* 是否可以减少字数但不损失执行信息；
* 是否出现为显得专业而添加的概念。

压缩时不得删除：

* 必要条件；
* 排除条件；
* 验收证据；
* 依据；
* 责任边界；
* 关键测试；
* 回滚条件。

---

# 二十八、Loop 9：回归与质量进化

每轮修改后重新执行：

* 正向测试；
* 反向测试；
* 边界测试；
* 排除测试；
* 冲突测试；
* 反事实测试；
* 受影响的历史回归测试。

比较：

| 指标      | 修改前 | 修改后 | 是否改善 |
| ------- | --: | --: | ---- |
| 未定义概念数  |     |     |      |
| 无法执行条目数 |     |     |      |
| 无法验收条目数 |     |     |      |
| 重复标准数   |     |     |      |
| 冲突标准数   |     |     |      |
| 过时依据数   |     |     |      |
| 待确认项数   |     |     |      |
| 测试通过率   |     |     |      |
| 总标准条数   |     |     |      |
| 平均单条长度  |     |     |      |

只有满足以下条件时才接受修改：

```lisp
(接受本轮修改
  (AND
    关键质量指标改善
    无新增重大冲突
    回归测试通过
    可维护性未下降
    (NOT 仅仅增加篇幅)))
```

否则回退。

# 二十九、质量评分

每项按 0—2 分评分。

| 维度    | 0 分    | 1 分   | 2 分    |
| ----- | ------ | ----- | ------ |
| 领域适配  | 错误套用模板 | 部分适配  | 映射准确   |
| 完整性   | 关键内容缺失 | 部分缺失  | 完整     |
| 原子性   | 多条规则混合 | 少量混合  | 一条一义   |
| 可执行性  | 无法直接执行 | 仍需解释  | 可直接执行  |
| 可验收性  | 无验证方式  | 部分可验证 | 均有证据   |
| 边界清晰度 | 大量模糊   | 少量争议  | 清晰     |
| 依据有效性 | 过时或无依据 | 部分有效  | 当前有效   |
| 可追溯性  | 无来源和版本 | 部分可追溯 | 完整可追溯  |
| 渐进性   | 阶段割裂   | 基本递进  | 产出逐层传递 |
| 可维护性  | 高度重复   | 部分复用  | 原子化可复用 |
| 简洁性   | 结构膨胀   | 尚可压缩  | 无明显冗余  |
| 回归可靠性 | 无测试    | 部分回归  | 全部通过   |

通过条件：

```lisp
(允许发布
  (AND
    领域适配等于2
    可执行性等于2
    可验收性等于2
    依据有效性大于0
    所有维度大于0
    无P0阻断问题
    关键回归测试全部通过))
```

# 三十、问题等级

## P0：阻断

会导致标准无法使用、严重错误或不可接受风险。

## P1：重大

会导致不同人员系统性得出不同结果，或关键场景无法执行。

## P2：一般

影响可读性、维护性或部分边界，但不会立即阻断。

## P3：优化

表达、排版或复用方面的改善。

Loop 优先处理顺序：

```text
P0 → P1 → P2 → P3
```

不得在 P0、P1 未解决时集中优化措辞和排版。

---

# 三十一、停止条件

满足以下条件时停止 Loop：

1. 连续一轮未发现新的 P0、P1 问题；
2. 关键标准均可执行和验收；
3. 冲突已解决或进入明确升级路径；
4. 关键测试和回归测试全部通过；
5. 依据当前状态明确；
6. 待确认项均有责任角色；
7. 继续修改只会增加复杂度；
8. 新版本相对旧版本没有明显质量提升。

默认最多执行 10 轮。

不得为了达到轮数机械循环。

超过 10 轮仍未通过时，输出：

* 阻断问题；
* 无法解决的原因；
* 缺失信息；
* 需要决策的角色；
* 当前可安全使用的最小范围；
* 建议暂停或降级的标准。
