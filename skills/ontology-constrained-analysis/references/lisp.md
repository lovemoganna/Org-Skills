# Lisp

Lisp 只固定已经理解清楚的业务结构。

Lisp 不是新的编程语言，也不是完整 DSL。

## 命名

优先使用本体中的 canonical 中文名称。

默认允许：

```text
AND
OR
NOT
BETWEEN
=
!=
>
<
>=
<=
COUNT
SUM
AVG
BY
```

只有真实需求无法表达时，才增加新运算符。

## 聚合边界

`COUNT`、`SUM`、`AVG`、`BY` 可以表达业务模式内部已经明确的聚合条件，例如次数、累计金额、平均金额和按主体归属。

它们不得用于描述 SQL 写法、查询步骤或分析流程。

判断标准：

```text
先用自然语言说清业务模式。
再用 Lisp 固定结构。
```

如果 Lisp 只是在翻译查询语句，则不合法。

## 推荐结构

单条件：

```lisp
(业务行为
  [可选公共上下文]
  条件)
```

多条件：

```lisp
(业务行为
  [时间窗口]
  (AND
    条件A
    条件B))
```

共同语义上提。差异条件下沉。

不得重复相同主体、场景、事件、时间范围或计算范围。

## 禁止事项

不得用 Lisp 表达分析流程或证据状态。

禁止新增：

```text
SIGNAL
FINDING
RETEST
EXPLAIN
DRIVER
ROBUSTNESS
RELATION
```

Signal、Finding、验证状态和证据状态由分析流程管理。

## 简化标准

业务人员不理解内部实现，也应能直接看懂表达式。

如果 Lisp 比对应自然语言更难理解，必须简化。
