# Validator：按 Gate 检查和修复

Validator 验证输入、语义、证据与交付，不定义新的业务规则。只检查当前阶段；失败时定位、修复、复验。下述专项要求与 `analysis-loop.md`、`ontology.md`、`runtime.md` 配合使用，不重复创建规则库。

## 所有阶段共用的检查

1. 当前事实是否来自**本轮有效证据链**？写清来源阶段与状态：已验证、待验证、失败。旧轮次、作废分支、Eval 和示例不继承为本轮事实。
2. 是否越过阶段边界，或使用用户禁止的数据、字段、工作表、引擎与参数？
3. 主体、原生粒度、单位、时间语义、关系路径、证据状态是否兼容？
4. 尚待验证的字段、条件、关系或阈值是否被写成已确认？
5. 每个 SQL 是否直接对应参数闭合的问题？实际 Result 是否可复核、与结论一致？
6. 继续下一步会否改变判断或增加新证据？没有信息增量即停止。

## Gate 1：本体与来源

**本体原子知识库：** 检查两表在 `ontology.md` 中规定的列、三级标签、原子唯一性、业务语义、主体、粒度、类型、单位、时间、合法关系、解释及证据来源。

- 真实数据任务：每个原子必须注明允许的数据表字段或可复核的派生来源；空白、臆测、禁用来源不通过。只按实际 Schema 填写，不用测试夹具补字段。
- 两张表按 `ontology.md` 的规范列名验收；原子来源列必须为 `证据来源`，旧名 `来源` 不能视为通过。运行时对照本轮 DuckDB 实际 `DESCRIBE` 的允许表与字段执行 `scripts/check_ontology_sources.py`；报表渲染时不得静默更名充当 Gate 1 通过。来源必须精确到当前允许表的字段，不能仅填表名。声称狭义类别的关系需用当前观测值集核查；脚本只核验结构、来源与显式声明的值域必要条件，业务语义仍独立人工/模型审查。
- 纯概念任务：允许标注可靠知识来源及“待验证”，但不得把未知字段当成真实数据事实。
- 相同事实不得拆成重复原子；属性、参数、事件、模式不得混类；无独立意义的技术碎片删除。
- 关系必须是主体|关系|客体的业务事实。JOIN 可执行、名称相似、类型匹配或 Lisp 可表达，均不单独证明关系合法。
- 本体规则库每条必须形成新的稳定组合语义；单个状态改名、SQL 查询步骤、测试验证流程、Dashboard 逻辑均不算规则。规则定义不得超过组成原子可证明的事实。
- Lisp 先有自然语言业务定义，再固定条件；检查命名、括号、聚合与主体范围。不得添加 Signal/Finding/证据状态运算符。
- Gate 1 必须先完成结构**和**业务语义验证；仅列齐字段、括号合法，不等于本体语义通过。禁止先执行分析 SQL、形成 Signal/Finding，再把后续本体标为已通过。使用 `scripts/check_run_lineage.py` 复核阶段时间、前置查询、来源检查回执和语义证据；旧探索 SQL 如含业务聚合/JOIN，不得隐瞒或重命名为结构勘察。

## Gate 2：指标、原子问题、SQL 与 Signal

**指标：** 基础指标中性；派生指标能回溯至基础指标。逐项核对主体、单位、粒度、分母、时间窗口和状态口径。没有 Signal 不影响合法指标登记，但不得为覆盖字段机械生成指标。

**单位硬门槛：** 每一条 SQL 都检查原生单位，包括探索、统计概览、验证及最终 SQL。跨币种法币金额、不同加密资产数量不得直接 `SUM`/`AVG` 或合并为一个数；写“不可汇总”标签不构成豁免。只有经过验证、时间语义相容的兑换口径才能跨单位聚合。

**时间与状态：** 按 `created_at` 分组且筛选 `status=completed`，只能表述“创建于该时间范围且当前状态为 completed”。不得称为“该时间内完成”；`completed` 不等于资金最终结算、余额变动或不可撤销。

**原子问题：** 每题必须能一次查询回答，只改变一个主要判断，并明确主体、指标、资产/Rail、状态、时间、比较对象、单位、粒度与不同结果将改变的判断。不闭合只能保留为方向，不进入 SQL；不得为“高、低、异常、集中、活跃”等词发明阈值。

**SQL：** 真实执行前检查枚举显式分支与未知值；`ELSE` 不得将未知枚举默认为另一已知值。失败、无结果、元数据、历史样本均不算真实 Result。每个实际执行至少保留 SQL、Result、可证明的范围、不可证明的范围。

**Signal：** 需要真实 Result、明确结构/差异、新业务信息和至少一个合法且可能改变判断的下一问题。内部合法比较无需机械要求外部基线；小样本可以描述当前样本，不得推广总体、趋势或异常。无信息增量保留普通 Result。

## 局部组合与跨对象关系

1. 仅从当前有效 Signal 沿已登记的本体路径扩展，不重新遍历全部字段；阶段 9 不执行新 SQL。
2. 候选状态严格三选一：非法、合法但暂缓、合法并激活。关系可达但证据不足、语义模糊或维度变化性未验证时应暂缓，不误判非法，也不激活。
3. 仅当当前**有效证据链**已证实某维度在 Signal 范围内为常量，才据此淘汰。肉眼观察或旧轮次验证不可替代。
4. 多跳可达不证明直接因果、资金来源、链上方向或兑换；关系仅继承逐边登记的原始语义。
5. 每个跨对象候选保留：关系路径、Join 键、两侧实际类型、必要规范化、空键/orphan、匹配率、基数、限制、验证状态和证据阶段。未在当前链验证的标“待验证”。
6. 不同原生粒度先分别聚合，再按合法比较粒度 JOIN；独立回算 JOIN 前后计数与金额，放大则停止使用。相同时间共变不等于因果。

## 复杂问题与 Gate 3

**问题形成：** 只使用已验证原子问题、真实 Signal、合法关系和阶段 9 已激活维度。写明全部参数、比较对象、预期改变的判断和关系前置条件。形成问题时不写提前结论。

**真实验证：** 严格顺序：关系执行前置检查 → 原样执行问题 SQL → 真实 Result → 一致性/粒度/单位检查 → 结果边界。阶段 9 未激活的 `country/KYC/network` 等维度不得在复杂问题 SQL 中临时加入。Join 错误、无结果、无增量均可停止分支。

**竞争解释：** 当前解释不是自己的替代假设。替代解释必须与已知事实兼容、能推翻或收缩当前解释、可由数据区分、不依赖未登记关系。只保留必要的 1–3 个，不凑数。小样本、缺历史基线等属于限制，不冒充竞争解释。此阶段不提前执行稳健性 SQL。

**稳健性：** 按具体竞争解释选择最小必要验证（例如单主体/极端值、分母、JOIN 放大、时间/单位、小样本敏感性）。保存实际执行、保留/收缩/推翻的判定及剩余限制；不机械完成无关全套检查。

**Validated Finding：** 仅在必要验证通过后升级。任何数值性 Finding 必须能从本轮实际 SQL Result 重算；报告脚本不能内置某个测试样本的金额、数量或结论，不能用生成器自己的固定断言代替独立核验。若有生成器，使用同结构、不同数值的独立数据验证输出会改变。明确区分已确认事实、合理解释、未解决问题、数据限制；不把关联变成因果，不把订单状态变成真实资金结算。

## Gate 4：Decision Value、Dashboard 与报告

- 只有 Finding 会改变观察、调查、资源、业务动作或管理判断，才具有 Decision Value。
- Dashboard 还需独立确认使用者/动作、持续观察或明确的一次性展示需求、稳定的单位分母时间口径、更新机制和相对报告的展示增量。不满足时明确不生成 Dashboard，保留可审计报告。
- 仅展示必要的已验证指标和证据，不能为图表数量或 UI 模板填充 TopN、装饰性 KPI 或诊断过程。
- 用户要求报告时必须创建文件；成功报告与阻塞审计报告不能互相冒充。SQL/结果、表/图、单位、标签、复制与渲染按真实环境检查。来源原始字节的校验和在授权与运行时允许时单独记录；无法取得时标“原始 XLSX SHA-256 未核验”，数据库哈希不能代替源哈希。

## Runtime、交付与修复闭环

- 源真实字节须进入执行环境；校验指定 URL、字节数、SHA-256、所用 DuckDB 与读取函数。仅得到 GitHub 元数据、文件网页或历史 SQL 结果不得推进分析。
- 用户锁定完整 SQL、原始 URL 或初始化次数时，不可默改参数。远程直读、VFS 暂存、四表一次物化分别验收，不得以其中一项替代另一项。
- 最终浏览器 Origin、CORS、GET/HEAD/Range、WASM/Excel、实际 SQL、统一格式/高亮、原生 Clipboard 需逐项实测；`set_content` 或模拟复制只算对应局部验证，不能宣称部署端到端通过。
- Runtime 无等价执行路径时必须生成错误原文、已验证项、未执行项、复跑命令、恢复条件及 JSON/Markdown/HTML 阻塞文件；交付阻塞文件不算完成业务分析。
- 发现问题先分为 Skill 规则、执行偏差、环境或测试错误；用最小用例定位。只修受影响原规则与阶段，随后重跑原失败用例和受影响下游，保留修复前后证据；不得靠硬编码测试答案通过。
- Eval/示例仅验证 Skill，不得给真实分析提供问题、阈值、SQL 或答案。定义校验不等于模型行为 Eval 通过。
