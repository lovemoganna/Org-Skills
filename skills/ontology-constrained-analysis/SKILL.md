# 本体约束业务分析

## 目标与范围

先理解业务世界，再决定算什么。用两张本体表限制问题空间，保留少量有证据、有决策价值的 Finding，而非罗列字段统计和 TopN。

严格遵守用户指定的数据源、允许/禁止对象、执行引擎、原始 SQL、参数、权限、时间及交付格式。未知标记“待验证”；不得借助历史结果、测试答案、示例或禁用数据补全事实。

## Runtime Gate

数据分析前锁定执行契约：引擎、来源 URL、读取函数、固定 SQL/参数、初始化次数、允许与禁止范围、最终运行环境。先实测网络、文件原始字节、扩展、读取函数、Origin/CORS（适用时）及内存条件。Gate 1 通过前，只允许结构、类型、样本值、空值和来源勘察；不得先执行业务汇总、跨表分析或寻找 Finding 后回填本体。

- 用户锁定完整 SQL 或远程读取路径时，逐字保留；仅修改用户允许的参数。同源字节暂存、VFS 注册不自动等价于原 SQL。
- 只锁定来源但未锁定读取路径时，可校验原 URL 的完整字节和 SHA-256 后，由原引擎读取；不得换源、换引擎或改取禁止对象。
- 本地 DuckDB 不可用或某次下载/扩展加载失败，不得直接终止：按 `references/runtime.md` 的候选执行环境路由，优先尝试可操作的官方 DuckDB Web Shell 或独立 DuckDB-WASM，随后尝试其他获授权的 DuckDB 运行时。只把实际执行且物化成功的 SQL 记为通过；没有浏览器操作工具时提供可执行入口并标 `EXTERNAL_EXECUTION_REQUIRED`，不得冒称已完成或已穷尽运行时。
- 用户要求每表只读取/物化一次时，按原 SQL 在同一会话物化；后续只引用物化表。每个步骤保存真实执行回执。
- 无可用等价路径时，停止数据推论并生成真实错误、复跑方式和恢复条件的阻塞审计文件；“报告已交付”不等于“分析已完成”。

浏览器、DuckDB-WASM、单 HTML、同源 GitHub 恢复、SQL 格式/高亮/复制和故障回退细则统一读取 `references/runtime.md`。

## 执行纪律

默认每次只验收当前阶段：执行、自检、修复、复验、通过后停止。用户明确要求一次性执行或连续自动修复时，逐 Gate 执行到底，不因阶段通过而中断；仅在数据、权限、证据或兼容运行时阻塞时停止。上游修复使证据失效时，必须重跑受影响下游。

**并行边界：** Runtime Gate、数据物化及各 Gate 的依赖检查串行。上游通过后，独立、只读、状态隔离的测试可并行，集中记录并验证回执；失败按同一根因合并修复，再顺序复验受影响的下游。无法安全隔离时退回串行并记录原因。

## 固定流程

```text
真实数据或明确业务概念
业务语义还原
本体原子知识库
本体识别规则库
高质量指标
原子问题
真实数据验证
Signal
本体约束下的局部组合
复杂问题
复杂问题真实验证
竞争解释
稳健性验证
Validated Finding
Decision Value
Dashboard
```

## 四个 Gate

1. **Gate 1 本体就绪：** 两张表通过结构和业务语义检查。真实数据分析必须逐原子记录可核验表与字段；缺必需来源即修复/阻塞。狭义类别或跨对象关系必须核对实际值域，来源检查器通过不等于语义通过；禁止先完成业务分析再追认 Gate 1。
2. **Gate 2 Signal 就绪：** 原子问题主体、范围、单位、时间和比较对象闭合，SQL 已真实执行，Result 有信息增量和合法下一问题；否则保留 Result 并停止分支。
3. **Gate 3 Finding 就绪：** 复杂问题先验证关系、执行 SQL、复核 Result，再提出能推翻当前解释的竞争解释并做必要稳健性检查；未通过保持 Signal。
4. **Gate 4 展示就绪：** Finding 具有 Decision Value 后，再验证使用场景、复用价值、更新口径和展示增量。不满足时交付分析报告，不强制 Dashboard。

## 必守规则

1. 字段是证据，不是业务定义。本体原子具有稳定、独立的业务语义；识别规则必须形成新的稳定组合，不能给单个属性或状态改名，更不能强化事实。
2. 组合只沿已登记关系。SQL 能 JOIN、多跳可达、同一用户关联均不证明直接资金关系或因果；跨对象 Join 验证键、类型、匹配和基数，原生粒度先聚合后连接，防止重复计量。
3. 指标须写明主体、粒度、单位、时间和依赖。基础指标保持中性；跨币种或不同资产数量禁止直接相加，**包括探索 SQL 和标注“不可汇总”的中间结果**。
4. 原子问题一次查询可答、参数闭合、不同结果会改变判断。没有明确标准时，不使用“异常、明显、主要、高低”等定性词，也不自造阈值。
5. 无真实 Result 不产生 Signal；Signal 不是原因。小样本与缺少外部基线限制解释，但不自动否决真实内部比较；无合法信息增量即停止。
6. 局部组合只沿当前 Signal 的关系与有效证据展开，区分“非法 / 合法但暂缓 / 合法并激活”。不得继承旧轮次、作废分支或 Eval 的事实。
7. 复杂问题验证时不得临时增加未激活维度。枚举 SQL 须显式处理未知值，不得用 `ELSE` 默认为已知分类。
8. 竞争解释、数据限制、稳健性检查分别处理。Finding 区分已确认事实、合理解释、未解决问题和限制；不得将当前记录状态扩展为最终结算或将关联扩展为资金来源。
9. 每个结论可追溯到当前有效本体、问题、实际 SQL、真实 Result 和必要复核。数值叙述必须动态取自本轮 Result；不得写死观察值、用固定样例结果断言自证正确，或以报告生成器自报 PASS 代替 Validator。没有结果时标“待执行”，不得虚构。
10. 最终交付遵守用户指定格式。单 HTML 的 SQL 使用统一格式、高亮和纯 SQL 复制；只有在**最终实际 Origin** 实测后才标记浏览器端到端通过，`set_content`/模拟 Clipboard 不能替代。

## 输出与停止

正常交付保留“业务语义 → 两张本体表 → 指标 → 原子问题 → SQL/真实 Result → Signal → 复杂问题及真实验证 → 竞争解释及稳健性 → Finding → Decision Value → Dashboard 决定”的追溯链。

数据无法核验、无合法下一问题、信息不增加、复杂度无收益时停止相应分支。指定报告即使无 Dashboard 也必须交付；数据被阻塞则交付阻塞审计报告并明确未完成业务分析。
