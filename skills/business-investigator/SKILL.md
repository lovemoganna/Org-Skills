# Business Investigator · 证据驱动的业务研究

**核心任务：让读者从原始数据里学到新业务知识。** 本 Skill 是研究编排入口，不是新模型、新 Agent 或替代 SQL 验证器。默认当前会话独立推进，不要求配置其他模型 API。

## 用户只需输入
业务领域/目标、数据源或文件、不可变读取与权限契约。允许业务目标宽泛（“先看懂这份表，再找最值得研究的现象”），不要求用户先选 UID、指标、疑似异常或报告章节。

不得更改原始 URL、Sheet 白名单、引擎、读取函数、数据版本、写权限。用户限定“每张表读一次并物化”的，后续探索只查询已物化表。无法在真实环境执行须明示 BLOCKED，不以历史运行回执冒充本轮实测。

## 研究循环（每轮只有一个有信息价值的问题）
1. **认识业务**：在允许的数据内检查真实 schema、字段语义、状态分布、时间、单位、记录粒度、关键实体及关联基数；先建立用户/订单/资产/行为的关系，不对陌生字段臆造意义。
2. **生成候选**：从已经观测到的事实提出多个竞争解释。每个候选回答三问：为什么值得查？哪条最小查询能够区分解释？不同结果会改变什么业务行动？选择证据可达、信息增量可能更高的候选；其他保留或明确舍弃。
3. **真实执行**：由 business-reasoning 完成结果表、JOIN 基数与 SQL 设计；通过实际授权引擎执行。Analysis Verifier 独立对账语义、粒度、异常值、时间及反例，不得由 SQL 成功运行推断业务结论正确。
4. **递进**：新 Result 可能证实、推翻或缩窄原假设。只有它改变问题、竞争解释或行动，才继续下一条 SQL。按真实对象沿 UID、订单、资金渠道、币种、时间展开，而不是机械枚举更多 KPI。动态选择对象，禁止把示例 UID 或答案写死。
5. **及时止损**：现有授权字段无法区分关键解释时标 GAP，说明具体缺少哪个事件字段/日志，终止这一分支；继续其他可验证线索。不得把“尚未查询”误写成“数据不足”，也不得因为缺少证据猜测违法。
6. **形成认识**：仅保留已核实的具体发现、反例、解释边界和可执行动作。反复统计、修改样式和增加角色轮次不算增量。

**研究状态保持**：当前问题；已经验证的事实；被推翻的解释；尚未验证的竞争解释；授权数据能够回答的问题；因为证据缺口而停止的分支；下一条查询为什么有价值。相同结论不得跨轮重复包装成新发现。

## 内部职责，不进入读者文章
- business-owner：必要时帮助评估某个发现能否改变真实业务决策；**不在看数据前锁死题目**。
- business-reasoning：设计查询和结果表，不给自己签验证通过。
- analysis-verifier：实际复算、检验伪关联、时间/状态语义及证据范围；不代替研究主控选择方向。
- loop-engineering-meta：诊断最早失败与内容质量，最小修复、反例重跑；没有实质信息增量时停止。

所有角色均是能力/职责划分。同一模型串行执行时不得自称独立的三个 LLM Agent。

## 正文交付门禁
**先看内容是否值得读，再决定是否生成 HTML。** 不以章节数、SQL 条数、字数、KPI 数、CI PASS 数代替研究价值。可只得到一条足够有深度的发现，不强制凑数量。

一篇可发布的业务研究文章应通过以下问答：
1. **新知识**：调查前不知道、调查后已经证实的事实是什么？跟普通数据排序相比多获得什么认识？
2. **为什么成立**：至少有可追溯查询结果、正确分母/基线、业务口径和能够挑战关键解释的反例。只有相近时间或相同 UID 不等于资金因果联系。
3. **所以怎样**：发现将改变哪种调查动作、监控口径、案件范围或明确的不动作？哪个证据缺口能改变当前判断？
4. **值得独立阅读**：去掉 Skill、编排、QA、CI 和泛泛的“下一步继续调查”之后，正文是否依然有业务理解价值？

未达到：交付简短的**研究记录**（已证实/被反证/无法判断/可行动缺口），**不要生成专业报告或 HTML**。达到：由真实发现自然决定文章结构，正文只谈业务、证据、解释和方法；SQL、QA 回执和 source revision 放可折叠证据附录或旁链，不占正文。

## 必须避开的典型伪发现
- 当前 frozen/active 状态不可回推历史订单发生时的账户状态；需状态变更生效时间。
- completed_at 非空不一定等于 status=completed；两者要分别验证。
- 同 UID、同日或 5 分钟间隔的法币和 Crypto 记录不能证明兑换/洗钱资金链。
- 同币种入出金差额不是当前余额；不同币种不可在不一致估值日期混加。
- 锁定的远程 Excel 不等于实时风控流，抽样交易不能估计全平台风险率。

## 验收与停止
- **技术验收**：已授权源身份、真正执行、JOIN/字段口径、反例与可追溯结果。
- **内容验收**：新增事实是否改变认知或动作；竞争解释是否处理；是否有无法证实的硬推断。内容未通过不能以技术 PASS 冒充。
- **停止**：达到决策所需最小证据；下一次查询不会改变认识；或缺失关键来源且权限不允许继续。不得承诺无限后台探索。
- 若只是小型教学样本，文章必须说明样本局限，不能包装成真实平台内部风险调查或违法定性。
