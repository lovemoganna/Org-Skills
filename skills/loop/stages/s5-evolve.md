# S5 · Evolve

只有在存在复现和证据时修复，按最早的可行动缺陷层归因：

| defect_layer | 可观察症状 | 行动 |
|---|---|---|
| S1 | 目标理解错误、未经授权的推测 | 修 IntentCard，重跑 S2 起 |
| S2 | 技术验收全过但目标没达成；验收/边界不完整 | 修 TaskSpec，重跑 S3 起 |
| S3 | 交接丢字段、缺依赖、错误编排 | 修 ChainSpec，重跑 S4 |
| atom | 原子提示单步遗漏、格式不稳或越权 | 只改该 atom 与其下游 |
| execution | 权限、工具、环境缺失 | 报告阻塞，不伪造 Loop 修复 |

每次只修改一个主要层面，重新运行受影响用例；最多两轮修复。没有新证据、出现关键回归或成本大于收益时停止。

## 沉淀
- 只有真实达标且可跨任务复用的规则才入 registry；初始 `draft`。
- `verified` 必须有至少两个不同真实任务的结果及可追踪验证证据，不能以模拟测试、静态检查、同一作者自评升级。
- 改变 stages 或 atoms 前后都检查 `evals/golden.md`；实际未运行的行为用例必须标“待核验”。
- 对应 run 存 Patch 和本次修复的回归证据。不制造无结果的运行记录。

产物：`templates/patch.md`。复杂运行时的基线/受控 A/B 和故障根因研究交给已有 `loop-engineering-meta`，不在此复制评估器。
