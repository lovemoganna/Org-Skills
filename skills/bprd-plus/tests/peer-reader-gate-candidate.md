# 候选增补：写作者盲读校验（只改变自检，不增加正文模板）
完成 BRD 后，在内部把最终正文交给“不知道原始需求、未读本 Skill”的开发者和测试者：让开发者逐条说出各触发状态的允许/禁止动作、失败/取消/重复事件处理；让测试者用同样正文写出能区分关键边界的 PASS/FAIL 用例。如果只能靠猜测才能作答，定位缺失的必要条件，修改最短的相关句子。原文未规定的核心取舍不得猜，列为待确认。
再将用户原始材料中的每条独立要求、例外和禁止行为与正文验收断言逐项反向对应。缺一项补一项，不得为了压缩删除关键区别；已经有对应且准确的内容不重复。
这些检查默认不进入最终 BRD；小需求做快速内检，避免过度增篇。
