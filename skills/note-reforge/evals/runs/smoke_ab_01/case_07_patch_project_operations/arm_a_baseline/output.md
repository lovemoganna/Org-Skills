这份笔记把项目管理工作分成四个关键闭环环节：启动与治理（立项输入）、相关方管理（方案与执行协同）、计划与执行（进度与质量把控）、复盘与积累（复盘沉淀与经验固化）。“坏问题的预防”是贯穿各环节的风险防范检查清单，不是第五个顺序阶段。〔补〕

* 先找对应环节
| 遇到的问题 | 先看 |
|----------+------|
| 目标、授权或决策机制不清 | 启动与治理 |
| 沟通无效或遗漏相关方 | 相关方 |
| 计划偏离、资源或进度受阻 | 计划与执行 |
| 经验无法复用、问题反复 | 复盘与积累 |
| 范围蔓延、变更失控等 | 贯穿各环节的风险预防 |

* 原始问题与处理环节

* 启动与治理

- *问题本质*：许多项目失败始于启动阶段的"急于行动"而非"充分思考"
- *方法论提升*：
  - 项目章程的正式确立（明确业务目标、范围基线与核心授权，避免仅靠口头约定）
  - 建立 RACI 责任矩阵（明确相关方职责与问责边界）：
    - *R (Responsible / 负责执行)*：具体任务的承接者与直接实施人。
    - *A (Accountable / 最终问责)*：对成果质量与交付成败负最终责任的唯一批准人（每项任务有且仅有一位 A）。
    - *C (Consulted / 咨询顾问)*：在任务推进前及过程中提供关键输入与专业意见的双向沟通方。
    - *I (Informed / 告知知情)*：需同步了解任务进展或交付结果的单向通报人员。
  - 设立项目治理机制（决策流程、分级上报机制、变更管理机制）

* 相关方

- *问题本质*：项目失败常源于"没听到正确的声音"或"忽略了关键相关方"
- *方法论提升*：
  - 建立相关方影响力-利益矩阵
  - 差异化沟通策略（不同相关方需要不同的沟通频率与方式）
  - 隐性相关方识别（如最终用户、监管方、间接受影响部门）

* 计划与执行

- *问题本质*：计划与执行脱节，或计划过于僵化
- *方法论提升*：
  - 里程碑与关键路径管理
  - 敏捷与传统方法的平衡（知道何时需要灵活，何时需要严格）
  - 定期计划评审与调整机制

* 复盘与积累

- *问题本质*：缺乏系统性的经验积累与改进。
- *方法论提升*：
  - 项目后评估：关注结果与过程双重维度。
  - 能力体系构建：将项目经验转化为组织能力。
  - 持续改进：项目管理是一个持续改进的过程，需要不断反思、总结、学习、改进。
  - 复盘会议：项目结束后，组织复盘会议，回顾项目过程，总结经验教训，形成改进措施。
  - 经验教训库：建立项目经验教训库，记录项目中的成功经验和失败教训，组织可复用的模板，供后续项目参考。
  - 最佳实践：学习和借鉴行业最佳实践，不断提升项目管理水平。
  - 培训与学习：鼓励项目团队成员参加项目管理培训和学习，提高专业技能。
  - 证据与推论边界反查：复盘总结必须以客观事实、可验证的执行记录为依据；凡无外部核验证据支持的新增推论或建议，必须明确标为【假设/待验证】，严禁冒充实测专家知识。

* 贯穿各环节的风险预防

- *计划不完善:* 缺乏详细的任务分解、资源估算、依赖关系分析等。
- *目标计划未对齐:* 缺乏对项目背景、目标、范围、风险等方面的充分讨论和确认。
- *相关方识别不全:* 忽视了关键决策者、资源提供者、最终用户、受影响的部门等。
- *沟通不到位:* 缺乏沟通计划、沟通渠道不畅、信息传递不及时、反馈机制缺失等。
- *范围蔓延：* 项目范围不断扩大，超出最初的计划。
- *资源不足：* 缺乏必要的资源（人力、资金、设备、技术等）。
- *风险管理不足：* 对项目风险识别不全、评估不准、应对措施不力。
- *质量管理不足：* 缺乏质量标准、质量控制措施不到位。
- *变更管理失控：* 对项目变更缺乏有效控制，导致项目失控。
- *团队协作问题：* 团队成员之间缺乏信任、沟通不畅、职责不清、冲突不断。
- *缺乏复盘：* 好的经验无法沉淀, 坏的教训一直重复。
