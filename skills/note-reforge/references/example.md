# 对照案例(示意"更好"是什么意思,不是模板)

## 案例一:提示词合集

症状:同一段"空白区域无法缩放"在三个小节各写一次,都写"仍无法",指令都是"重新检查";
"自主优化"那条后面写着"效果比较垃圾";一条要求彻底重构,另一条要求最小修改;UI 审查提示有三个长度。

弱:

- 逐节润色,仍是三节重复。
- "原文标注:自主优化效果垃圾,建议避免开放式提示。"(审读口吻 + 经验升格)
- "在小步修改与重构之间需要平衡。"(抹平冲突)
- "三个长度版本各有适用场景。"然后没说是哪些。

强:

- 入口表:"同一个 bug 提了两次还在 → 第四节"。
- 第四节以症状命名,第一人称:"这个症状我写过三次,措辞几乎一样,每次都让它重新检查,
  没有给它新信息,我也没记最后有没有修好。"给取证模板,标题标一次〔补〕。
- "自主优化"保留原话评价作为反例,改法写成默认建议。
- 两对冲突并列写出出处,给默认读法,标一次〔补〕,并说明当时没有调和。
- 短版与完整版差异大,就逐字保留短版,再给带理由的选择建议。

## 案例二:有分工的教程系列

症状:三份笔记(01 基础、02 工程、03 验证)互相回链,01 自称"三模块入口";
一个 verifier 脚本按三个文件边界读取;03 末尾夹着"维护生成教程的 Skill 的补丁台账";
03 自己写明原生 E2E 为阻塞、整体部分通过;
有些 `file:...::*4. 参数传递` 链接指向的标题在目标文件里并不存在。

弱:

- 没人要求合并就合成一篇,还写"你要求合并,所以合并"。
- 副标题写"实测记录"。
- 把几个参数的差异压成一张"是否计算"的表,其中一格语义错误。
- 删掉 `#+DESCRIPTION`、`#+OPTIONS`,`#+filetags` 只剩公共部分,回复里却说"文件头原样保留"。
- 台账留在主体;补一段引用未定义函数的 Elisp 草稿。
- 回复末尾附一张"问题 → 已解决"对照表。

强:

- 三份各出一份下一版,保留分工;01 本来就是入口,就沿用,不另建索引;台账拆成单独文件。
- 链接改成 CUSTOM_ID,并在回复里说一句"原来指向 01 的 `::*4. 参数传递…` 与 01 实际标题不符"。
- 导语分开说:哪些块有记录,哪些只有预期值,整体仍是部分通过;
  `#+RESULTS:` 的出处不推断,写"我没逐块记"。
- 文件头逐项照抄;`#+filetags` 各保留自己的词。
- 回复只有:文件路径,和"verifier 若按旧文件名读取三份,要改读 .next""台账已拆出"这类影响使用的事项。
