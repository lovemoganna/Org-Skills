# 笔记形态参考

先判断原文属于哪类,再决定骨架。骨架是起点,不是模板,混合型就混合。

## 提示词 / 模板合集

- 开头:"我现在的情况 → 用哪条"的入口表。
- 每条:适用情形、逐字提示词(代码块,填空处用 [ ])、记录过的效果、不适用情形。
- 同一提示的多个长度版本合并为一条,按"多版本的处理"规则保留。
- 反复重发的同一症状收成一个条目,记录"提了几次、措辞怎么变";没记结果的写成缺口。
- 被作者评价为差的提示保留为反例,附评价原话。

## 操作手册 / Runbook

- 开头:什么时候用、前置条件。
- 主体:步骤,每步写预期结果与出错时看哪里。
- 末尾:回滚、已知坑、验证方法。命令、路径、参数逐字保留。

## 排障记录

- 以"症状"为标题。每条:症状 → 已试过的 → 有效/无效 → 根因(确认过的与推测的分开)。
- 未解决的保持未解决,不补结论。

## 决策与复盘

- 当时的情境和约束、备选方案、选了什么、为什么、后果。
- 没写后果的,写成缺口,不替作者推演。

## 学习笔记 / 概念笔记

- 以"想弄懂什么问题"开头。写出概念之间的关系(谁依赖谁、谁和谁易混)。
- 作者自己的例子和类比必须保留。易混点单列。

## 阅读 / 资料笔记

- 作者观点和摘录分开,引文不改一字。保留页码、链接、出处。
- 补"这条资料能回答我什么问题"。

## 项目 / 系统笔记

- 当前状态、关键决定、已知问题、下一步。路径、仓库、环境、依赖版本逐字保留。
- 过期信息不删,标注原文日期。

## 教程 / 实验记录(带可执行代码和执行结果)

- 开头:环境记录和证据状态。哪些块有执行结果,哪些只有预期值,哪些被标阻塞,分开说。
  标题和导语不得强于这份状态。
- 主体:按"我想做什么"组织,每个能力保留代码块和结果记录。
- 末尾:验证方法与矩阵;"症状 → 先看哪里"。
- 不同环境、日期的执行记录分别标注。出处原文没写就写"我没记"。
- 与教程本身无关的维护台账、工具链过程日志,拆出去。

## 系列笔记(多篇有分工、互相回链)

- 默认每篇各出一份下一版,保留分工,更新彼此链接(改成 CUSTOM_ID 链接)。
- 系列已有入口篇就沿用,在入口里放全系列的"我遇到什么 → 去哪篇";没有才新建索引。
- 每篇自己再放一份本篇范围内的"症状 → 先看哪里"。
- 绑定文件名的脚本、配置,在回复里点明需要同步。
- 合并是用户明确要求时才做。
