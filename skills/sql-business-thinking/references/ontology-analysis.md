# 本体约束分析协议

目标：用于陌生多表数据集或完整自主分析。先理解数据描述的业务世界，再生成指标和问题。简单单题保持原快速通道，不强制启用本协议。

## 1. 分析语言

用户可见分析语言统一使用中文：

Gate 称“阶段”。
Signal 称“分析信号”。
Question Frontier 称“问题边界”。
Hypothesis Frontier 称“假设边界”。
Finding 称“发现”。
Validated Finding 称“已验证发现”。
Robustness Check 称“稳健性检查”。

历史测试名、机器文件名、状态码和运行时接口可以保留英文。最终业务正文不得把内部英文术语直接当作用户可见标签。

## 2. 本体前置阶段

正式指标分析前先完成业务语义还原。识别业务对象、事件、主体、关系、粒度、单位、状态和时间语义。

随后先生成两张表。

### 2.1 本体原子知识库

至少包含：

| 一级标签 | 二级标签 | 三级标签 | 原子名称 | 原子层级 | 本体类别 | 类型 | 单位或值域 | 知识点解释 |
|---|---|---|---|---|---|---|---|---|

原子必须具有稳定业务语义，并能独立参与关系、计算、判断或组合。不得机械复制全部字段。继续拆解不能产生新的独立业务语义时停止。

### 2.2 本体识别规则库

至少包含：

| 一级标签 | 二级标签 | 三级标签 | 识别标准 | Lisp 表达式 | 规则定义 | 当前状态 |
|---|---|---|---|---|---|---|

本体识别规则只描述“业务上发生了什么”以及“基础业务行为可以组成什么有意义的模式”。

方向字段只描述行为方向，不自动证明业务结果已经完成。存在独立状态字段时，必须区分“方向行为”与“已完成行为”。例如 `direction = deposit` 只能定义“入金方向交易”；只有再满足明确完成状态，才可以定义“已完成入金”。

GROUP BY、JOIN、SUM、TopN、完成率计算、数据质量检查和稳健性检查属于分析或验证方法，不得写成本体识别规则。

判断标准：主要描述“怎么算”的内容不进入本体识别规则库；主要描述“发生了什么业务行为”的内容才可以进入。

## 3. Lisp 结构锚定

Lisp 只负责固定已经理解清楚的业务结构，不负责推理，也不是新的编程语言。

业务对象、行为、原子、指标和参数优先使用本体中的 canonical 中文名称。只保留必要的通用运算：AND、OR、NOT、BETWEEN、=、!=、>、<、>=、<=、COUNT、SUM、AVG、BY。

禁止为了描述分析流程创造 SIGNAL、FINDING、RETEST、EXPLAIN、DRIVER、ROBUSTNESS、RELATION 等新运算符。

共同内容上提，差异条件下沉。业务人员无法直接理解 Lisp 时，继续简化。

推荐结构：

    (业务行为
      [可选公共上下文]
      条件)

组合行为：

    (用户
      [时间窗口]
      (AND
        业务行为A
        业务行为B))

## 4. 指标阶段

两张本体表完成后才能提炼高质量指标。

D07 的任务不是建立通用指标语言，也不是枚举所有可计算组合。D07 只做一件事：**从当前合法业务世界中生成少量候选指标，并淘汰低价值指标。**

每个候选指标只需要说明：指标名称、业务意义、统计主体、结果粒度、单位或口径、当前状态。

候选指标必须同时满足：

1. 能回溯到 D05 原子或 D06 业务规则。
2. 当前数据能够合法计算，或限制条件明确。
3. 不同结果有可能改变后续分析判断。
4. 不只是因为字段存在或技术上能 COUNT / SUM / GROUP BY 才生成。
5. 不与已有候选指标表达同一业务问题。

D07 应控制候选数量。优先保留少量能够回答“规模、结构、状态、重要业务模式”的指标。没有新增判断价值的切片、排名和组合直接淘汰。

结果粒度与分析范围必须分开。结果粒度回答“一个结果代表什么层级”；分析范围回答“使用哪些记录”。“当前授权数据全集”只能作为分析范围。

金额或数量指标名称必须忠实于源记录能证明的事实。只有订单或交易记录时，使用“订单金额”“交易记录资产数量”等中性名称；不得把方向记录直接命名为“实际入金金额”“实际提币金额”。即使 status = completed，也不得在没有额外业务定义时自动升级成最终结算事实。

带时间范围的指标必须明确时间字段、起始时间、结束时间、边界和时区；未指定时间过滤时，明确写“当前授权数据全集”。

比例必须引用明确的分子和分母；两者使用相同分析范围、时间字段、边界和时区。分母为 0 时返回 NULL / 不适用。

DISTINCT 主体数不可跨时间窗口直接相加。比例、平均值和其他非加性指标不可跨范围直接 SUM 或简单 AVG。交易记录数只有在切片互斥且没有重复时才能相加；原生单位金额或数量只有在单位一致、切片互斥且记录不重复时才能相加。

不得把方向状态、处理状态或中间状态自动命名为“成功率”“完成率”“处理效率”。

具体 SQL、维度下钻和指标实例化留给后续问题阶段。D07 不建立额外指标 DSL，不要求维护“指标模板 / 指标实例”两层体系。

## 5. 原子问题阶段

由高质量指标生成最小可验证业务问题。一个原子问题只改变一个主要判断，并能通过明确数据验证回答。

每个问题说明：依据哪个已保留指标、为什么现在问、不同答案会改变什么、当前数据能否回答。允许零个合格问题，不为凑数量机械切分字段。

状态必须保留业务含义：进行中（pending / processing / confirming）不等于终态非完成（failed / cancelled）；源系统未给出终态定义时不能自行推广。少量非 completed 记录只能触发谨慎核查问题，不能据此预设渠道、网络或方向有系统性差异。D03 已经回答的状态计数不再包装成新问题。

## 6. 分析信号阶段

原子问题得到真实 Result 后，先解释绝对笔数、分母、比例，再检查状态构成。总体比例接近，不代表底层状态具有相同业务含义。

只有不同结果可能引发不同后续判断时，才保留分析信号。少数记录的状态构成差异只能标为受限描述性信号，不能推断显著性、系统性异常或原因。历史记录中的 pending/processing 不能称为“当前待处理”；failed/cancelled 不能一律称为“失败”。

分析信号只是值得继续核查的观察，不直接升级为已验证发现，也不在此阶段新增问题或 SQL。

## 7. 本体局部展开阶段

发现分析信号后，不重新扫描全部字段，也不枚举所有原子的组合。

只激活与当前分析信号存在合法关系的本体邻居。每增加一个维度，必须说明该维度为什么可能改变当前判断。无法说明时停止该组合。

复杂问题必须引用至少一个已经验证的原子问题或分析信号，并同时满足主体、关系、粒度、单位、时间语义和结构兼容。

本体负责判断“能不能问”。问题价值判断负责决定“值不值得继续问”。

## 8. 验证与停止

进入 SQL 的问题继续使用现有问题质量、竞争解释、诊断验证和稳健性机制。

不设置固定轮次。继续分析必须存在未解释的高价值分析信号，并且能够沿合法本体关系提出可能改变当前判断的新问题。

出现以下任一情况时停止当前分支：没有新的合法关系可以展开；新问题不会改变判断；数据无法继续支持；只剩低价值描述切片；继续组合只增加复杂度而不增加有效信息。

## 9. 验收

完整分析任务必须满足：

1. 先还原业务语义，再生成两张本体表。
2. 本体识别规则描述业务模式，不描述查询技巧。
3. 指标从真实业务对象、业务模式和数据能力产生。
4. 原子问题可以独立验证。
5. 分析信号不能直接当原因。
6. 分析信号后只沿合法本体关系局部展开。
7. 复杂问题必须从已验证原子问题或分析信号逐步生长。
8. Lisp 必须人类可读，不得演变成复杂 DSL。
9. 没有真实 Result 不得继续推论。
10. 已验证发现才能进入最终决策层。Dashboard 另做看板资格判断；简单但长期重要、可重复监控的数据，不要求先形成深度分析发现。


## 10. 调查价值与行为关系验证（仅深度 Report/Autopilot）

**Discovery Breadth Gate：**先判断哪些业务关系在授权数据中真实可观察。当数据同时包含主体、事件时间及行为类型时，在宣布“只剩金额或比例信号”之前，至少评估一个与本次业务目标有关的事件顺序、重复行为或跨事件关系候选。候选必须由数据能力和已有信号触发，不机械枚举字段组合。不相关或无法验证时记录淘汰原因；不得强制产生风险发现。

**Result-Driven Investigation Gate：**每个选中问题记录触发的已验证证据、两种不同答案会改变的判断、真实 SQL/Result 的 run、data、Skill revision、Result 后判断变化以及下一问或停机原因。不得把预写的统计 SQL 清单当成问题循环；只有新 Result 才能触发动态下一问。D13/D15/D16 发现新问题应回 D08/D09 再决定是否执行。

**Temporal Relationship Gate：**检验同主体入/出金、重复订单、跨来源行为时，必须区分创建与完成时间，检查时区、同币种/金额/渠道、状态和事件顺序；观察时间窗口需要业务假设依据，不能变成未经授权的通用风险阈值。相邻时间、同 UID、同金额或 completed 标签不自动证明资金闭环、结算、对手方关联或可疑交易。缺少余额、收付账户、地址归属及真实结算证据时，资金因果关系保持 unresolved。

**Hypothesis Discrimination Gate：**重大调查性信号至少并列两种有不同可观察预测、可被反驳的解释。设计并真实执行能区分它们的最小检验与一次负控/替代口径/稳健性检查；检验无法运行或不能区分时，不得把“列了竞争解释”写成分析深度 PASS。主体重叠若几乎由集合规模决定，或 TopN 只是分布描述，不能独立冒充调查模式。

**Investigation Depth Gate：**D17 对调查型主发现保留具体主体或事件证据、H1/H2、实际诊断与稳健性 Result、判断变化、结论边界；D18 仅将证据足以改变明确调查决定的发现晋级。D20 优先交付核查对象、行为关系、反证、证据缺口和最小下一步。仅能证明描述性事实时使用 `DESCRIPTIVE_ONLY` 或 `NO_DECISION_GRADE_FINDING`，不因 SQL/Gate/渲染全绿而宣称“深度分析通过”。机器证据链校验仅证明引用及依赖结构，不验证业务真值。
