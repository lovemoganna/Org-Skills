# Loop · “说人话”反向质检（同会话试跑）

## 真正的缺陷与最早根因

用户要求炼化逐步推进的 Vibe Coding 提示，以便复制到外部 Coding Agent 使用。上一版 Loop 把这项任务扩大为带“阶段 A/B/C/D”“验收表”“执行边界”的长篇规约。虽有工程依据，却增加了用户读完、复制和修改的成本。

查到的最早原因不是“用户意图没识别”，而是 `SKILL.md` 原 Section 12 默认强制显示 `Result / Evidence / Loop QA / Consolidation` 技术报告格式，且缺少**面向读者的语言验收**。之前只有任务质量门禁，没有检验“用户看得懂、拿去就能用”。

本轮修复 Output Contract，并将可读性纳入 G3。要求在内部保留必要证据，不在用户正文强制展示内部流程。以下输出来自本次同一 ChatGPT 会话，**不是独立模型多轮测试**。

## 实际对照 1：外部 Vibe Coding 提示

**用户真实目的：** 产品更专业、顺手、适合初学者；外部 Coding Agent 自主审查、实施和测试；不重复开发、不盲删教学说明、不擅自合并上线。

**原输出方式的缺点：** 多个强制标题、阶段、列表和交付模板，把 Prompt 设计方法写成用户要阅读的内容；后续用户明确提出“说人话”。

**本轮自然话改写（实际生成）：**

> 请帮我把当前数据分析产品做得更专业、更好用，尤其要让第一次接触透视表的人也能轻松上手。先看看现有界面、代码和功能，找出最影响使用的真实问题，比如布局乱、行列和指标难理解、操作绕、说明太多。已经做好的功能不要重做；无用的内容可以精简，但真正有帮助的新手提示要保留。
>
> 你自己选一两个最值得解决的问题，直接修改代码并测试，确保导入、计算、筛选、撤销、导出和不同屏幕上的操作没有被破坏。参考优秀产品的设计品质，但别为了炫酷增加无用装饰，也别自己宣布达到了获奖水准。请在可回滚的分支里改，不要未经允许上线。最后简要告诉我改了什么、实际测试怎么样，以及还有哪些问题没解决。

**本轮人工语义检查：** 原始目标保留；AI 主动执行、证据与权限保留；没有把“删除废话”误作删除新手帮助。删除了内部 A/B/C/D 等提示链术语。不能由同一模型自己的认可推断真实用户满意。

## 实际对照 2：跨领域的知识库清理提示（不依赖 Vibe Coding 案例）

**目标：** 把零散技术笔记整理成别人能读懂的文章，来源必须可靠，已有有效内容不覆盖。

**本轮自然话改写（实际生成）：**

> 请看看这批技术笔记，帮我整理成一篇人能顺着读懂的文章。重复的话删掉，专业词第一次出现时解释清楚，不要改掉原来的结论，也不要凭空补事实。先核对现有材料，再直接整理正文；拿不准的地方标出来，不要装作已经证实。保留原文件和可追溯的修改记录，最后告诉我整理好了什么，还有哪些需要核实。

**本轮人工语义检查：** 保留来源核对、实际整理、不能编造、原始保留与未证实提示；没有为独立文章任务强行生成 Loop 实验步骤。

## 负例：不应为了“说人话”抹掉重要限制

- 对金融、法律、医疗、数据删除、账户权限、正式发布等高影响结果，必要的风险和权限说明必须保留，哪怕答案需要更长。
- 如果用户要完整评估表、技术规范或引用与复现信息，不能任意缩成两段。
- 若模型只写“请全面优化直到完美”，却丢掉用户目标、测试、授权和失败说明，则视为**意义损失**而不是成功的简化。

## 结果和边界

本次读回的 Skill 规则应当满足：用户成果先于过程；面向读者的普通话表达；复制型提示独立可用；证据、权限和未完成状态不能被简化抹掉；技术报告只在需要时提供。

这份记录是同会话 A→B 风格改写和语义自检，不是盲评、不等于后续模型调用已经遵守。GitHub 回归只是检查规则/代码没有意外损坏，不能证明真实用户可读性提高。生产 main 不因本次单轮测试而自动合并。
