# Suno Songwriting · 原创华语音乐创作 Skill

## 定位与边界

把创作意图转为**能直接粘贴至 Suno 的制作规格和歌词**。优先旋律可唱性、语言自然、时代共鸣和有画面的情感表达；批判要有对象、证据感或可感知的荒诞，不写空洞说教。

- 本 Skill **仅生成创作文本及可验证规格**；没有实际生成/试听时，不声称歌曲已演唱、已发布、BPM/调性已被实测、音色效果已达成。
- 风格要用流派、编曲、演唱技巧、情绪等可操作词描述；不以具名在世艺人的个人声音或具体作品作声纹模仿目标。
- 用户给定名称、语言、时长、核心意象和版本时严格保留；自行推断项均标记“建议”或“默认”，不得伪称用户指定。
- 发布、上传、版权归属、分发与实际音频后期处理不属于本 Skill 的自动权限；另行使用相应能力并检查权限。

## 输入决策

读当前请求与会话中最近的明确参数，后来的指示只覆盖同名维度。

| 字段 | 优先级/默认 |
|---|---|
| `theme` | 用户给定主题优先；缺失时采用可逆的具体主题建议，不凭空断言用户偏好 |
| `title` | 用户指定的标题不可擅改；未指定时建议 3–6 个汉字、有记忆点 |
| `mood` | 用户指定；否则根据主题选择 2–3 个情绪标签并注明建议 |
| `audience` | 明确就遵循；未知可省略，不猜年龄/身份 |
| `genre / tempo / vocal / language` | 用户指定优先；否则给一套能相容的建议参数 |
| `version` | 首稿 `v1.0`；基于反馈局部升级 `v1.1`；主旨或结构重大重做 `v2.0`；不要伪称实际上线版本 |
| `constraints` | 时长、禁用元素、配器、分段、风格提示 ≤1000 字符等逐条保留 |
| `source_lyrics / source_audio` | 作为对照材料，区分“草稿”“生成版本”“经核验转写” |

信息不完整但仍能交付时先采用可逆默认并明确说明，不以多轮问卷拖延创作。只有缺少不可替代的主题或文本且无法给出有效候选时才问一个关键问题。

## 任务路由（先判产出范围）

- **full-song**：用户要求创作新歌或重写整首歌；交付完整六段结构和验收。
- **revision**：用户指定只强化副歌、Bridge、歌词或某一项参数；**只输出所要求的变化**以及必要的上下文和变更说明，保持未授权部分不变。若要求「升级整首歌」则按 full-song 全量交付。
- **style-only**：用户仅要求压缩、润色、翻译 Suno Style Prompt；**仅返回可复制 Style 文本及必要的字符计数**，不可追加歌词、简介或其他原本的全曲栏目。若原文缺失且不能从会话恢复，只问索取原文。
- **audio-compare**：用户请求核对实际音频；先验证文件、可用听取/转写路径，再列出草稿与可核验实唱差异；不自动重新创作或发布。

标准交付顺序只适用于 `full-song` 和明确要求整首升级的 `revision`。其余分支遵守用户的最小输出范围。

## 创作与输出工作流

1. **定主题**：写一句戏剧冲突：“谁在什么场景里想要什么，却被什么现实阻拦？”确定第一人称/第三人称视角、情绪转折及核心一句 Hook。
2. **旋律优先写骨架**：主歌安排可见画面，预副歌制造张力，副歌重复短而有辨识度的词组，Bridge 给出新事实或立场反转，Outro 回收开篇意象。结构可按音乐需求微调。
3. **控制语言和韵脚**：每句 8–12 个汉字为建议而非硬阈值；Hook/英文短句可更短，长句须能分气口。主押韵可选择 AA、AABB、ABAB，但不为押韵牺牲自然语序。
4. **中英混搭（若选）**：英文必须承担人物语气、社会压力或叙事反转等功能；先定义每个英文 Hook 的语义角色，再安排可唱的音节。避免译文重复、语法生硬和随机插入英文。
5. **写 Suno 规格**：输出 `Genre / Mood / Tempo / Instrumentation / Vocal Style / Production`，另给一个 **≤1000 个 Unicode 字符**的英文 `Style of Music` 可复制文本。该长度是本 Skill 的交付目标，不宣称适用于所有 Suno 产品版本。不得把整段歌词填进 Style。
6. **输出源码**：`Lyrics` 使用 `text` 代码块，歌词以 `[Verse 1]`、`[Pre-Chorus]`、`[Chorus]`、`[Verse 2]`、`[Bridge]`、`[Final Chorus]`、`[Outro]` 等分段标签组织；音乐制作指令只写在 `[ ... ]` 标签中，歌词正文不写创作解释或注释占位符。
7. **质检后交付**：按 `references/quality-gates.md` 校验硬约束，再按 `references/creative-rubric.md` 做歌词审读。若未听到实际音频，韵律/演唱效果只能标记“待试听”。

## 完整歌曲交付顺序（full-song）

1. **《歌曲名》 · 版本**，后接 100–150 个汉字的创作简介（统计汉字数；标点和英文不计入）。
2. **Suno 曲风参数**：Genre、Mood、Tempo、Instrumentation、Vocal Style、Production，注明建议与已指定参数。
3. **Style of Music**：单独的 `text` 代码块，控制在 1000 字符以内；不夹杂 Markdown 说明。
4. **Lyrics 源码**：单独的 `text` 代码块，完整分段与重复副歌；纯歌词不混入演唱分析。
5. **旋律/编曲意图与韵脚**：仅解释真正影响实现的 Hook、段落张力、情绪转折。
6. **版本变化与边界**：仅在迭代时列出保留项、修改项、尚待试听项。首稿后以一句紧凑提问征询曲风、歌词强化部位及多语言版本，不强迫用户逐项作答。

对完整歌曲可压缩解释但不可省略用户指定的歌词或 Style；对 `style-only` 和局部 `revision` 禁止套用完整歌曲模板。

## 音频与草稿核对分支

若用户提供已生成音频：先确认可读的实际文件或工具结果；文件不可访问就说明不能核验。把**创作阶段歌词**与**实际唱出的歌词**分层记录；只有确实听到/读取转写时才写“音频中唱到……”，难以辨认的句子标不确定。用户只请求改提示词时不启动音频核对。实际发布须另行授权，不因拿到音频就自动部署。

## 失败处理与迭代

- 风格提示超长：先删重复的形容词和制作同义语，优先保留流派、情绪、速度、人声、配器、Hook 与负面约束，再**重新统计**。
- 歌词过长/不顺口：标出行号，缩短最难演唱的句子；保持角色视角和叙事因果，不逐句机械压成同字数。
- 讽刺沦为说教：把抽象主张替换为**场景 + 行为 + 荒诞后果**；至少留下一个人物情感锚点。
- 中英切换生硬：删除无叙事功能的英文；将关键英文分配为“伪装 → 外部命令 → 自我承认”等明确转折。
- 版本修改先做局部修正；用户指定只改某部分时不得顺带整体重写。保留 v1.0 / v1.1 / v2.0 清晰标识。

## 可选加载

- 每次交付前读 `references/quality-gates.md`；重点追求歌词表现时再读 `references/creative-rubric.md`。
- 需要严格的输出格式时参考 `references/output-template.md`。
- `scripts/validate.py` 校验本地 Markdown 产物和 Style 字符数；`--mode style-only` 只校验风格提示。静态通过**不代表听感优秀**。
- `evals/evals.json` 是可执行/人工复核用例清单；未真实运行的用例不得宣称通过。
