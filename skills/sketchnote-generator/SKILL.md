# Sketchnote Generator

## 目标

把真实材料转换为一张具有一致视觉风格、清楚知识结构、可信事实边界的中文手绘知识信息图。图像是最终产物，不是提示词或设计说明。除用户指定外，默认简体中文、竖版 4:5、适合移动端阅读。

## 输入与执行门槛

1. 接受主题、正文、URL、文件或参考图；继承用户明确指定的语言、尺寸、读者、重点和保密条件。没有指定的非关键视觉参数自行决定。
2. 优先读取用户给出的完整材料。URL 无法获取时不能假装已读取；必要事实缺失且无法验证时，询问最少的关键问题。只有主题、没有具体事件材料时，可制作一般知识图，但不能编造特定案例事实。
3. 检查工具能力。优先调用实际可用的图片生成工具；不得只返回图像提示词冒充成品。若无图片工具但有可用 SVG/HTML 渲染环境，可以制作简化的静态 SVG/PNG，并明确它不等同于生成式手绘插画；两者均不可用则说明无法直接交付图片，不得虚报生成成功。
4. 若用户仅要求文字解释、可编辑结构化图或交互页面，不擅自使用本 Skill 替代该输出。

## 执行流程

### 1. 证据与信息提取

- 从原始材料提取主题、对象、属性、关系、事件时间、过程、数字、来源、行动和限制条件。
- 需要外部事实时优先核查可访问的一手资料。不能核实时标记不确定，不补造名称、数字、引文、链接或结论。
- 严格区分事实、合理推断、未证实信息；不得把关联写成因果、调查写成定罪、计划写成已经执行。不同司法辖区规则分别核验。敏感隐私和内部机密不公开。
- 按主要知识问题去重，不改变原文核心意思；不要把原文机械缩成标题清单。

### 2. 设计信息结构

- 根据材料复杂度组织通常 6–8 个模块；只有 2–5 个要点时相应减少，不能凑数。每个模块回答一个问题，具有短标题、关键信息和恰当的视觉形式。
- 先判断关系，再选图：时间演进用时间轴；主体与关联用关系图；执行步骤用流程；证据核查用清单；差异用对比；判断与边界用强调框。
- 采用“问题/背景 → 核心事实 → 机制或关系 → 执行或影响 → 结论/边界”的阅读链。并非要求固定五段或固定行业模板。
- 先压缩重复信息，再排版；不能靠缩小字号挤入更多文字。无法同时容纳必要事实与可读文字时，提示拆成系列图，不能默默删去证据边界。

### 3. 固定视觉系统

- **底材**：温暖米黄色横线笔记纸，轻微纸纹，左侧黑色螺旋装订，正面平视，无透视畸变。
- **文字**：醒目的深海军蓝中文手写主标题，红色短下划线；模块标题为深蓝粗手写字，配青绿色下划线；正文中文清楚可辨，保持三级字号层级。
- **配色**：深海军蓝负责文字/图标/轮廓；青绿色负责章节标记/连线；珊瑚红负责警告/风险/重要边界；浅黄色负责关键日期/数字背景；米白负责内容容器。不得堆叠无意义装饰色。
- **版式**：上方放主标题、右上角小型红框主题标签和一句价值摘要；主体默认双栏、自上而下阅读，圆形数字编号，配语义正确的线条手绘图标；底部用连续箭头总结关键逻辑或下一步行动。
- **手绘质感**：箭头、边框、图标、圆圈和标记保留细微自然笔触；不要商业 PPT、科技仪表盘、3D 渲染或大量剪贴素材。
- **证据位置**：需要引用时放简短的来源名称、文件标题/日期；完整长 URL 可在图外附上，不强行缩小字号。用户提供的参考图用于风格对齐，不得无依据复制其中的案例数据。

### 4. 生成与检验

- 在实际图像生成工具中提交完整信息结构和视觉约束，直接生成图片；无必要不展示中间分析。
- 生成前核查：主体、日期、数字、关系、重要限定词与模块间逻辑。
- 生成后核查：中文错字、遗漏、图形关系、箭头方向、文字遮挡、字号、越界、裁切、背景与色彩一致性。
- 工具允许查看和重生成品时，优先针对实际缺陷作最小修复，不随意重绘已正确内容；避免多轮无增益重试。
- 图像模型可能写错密集中文。未经逐字复核，不能宣称已验收。法律、财务和技术类关键表述应提醒用户发布前复核原始材料。
- 最终优先只交付图片。若无法生成、材料不完整或存在必须人工复核的问题，简短说明具体阻碍，不虚报通过。

## 多结构图与 Org Museum 集成（V2.4 实测补充）

仅在用户明确要求多图方案或发布到网页时启用；原有单张 Sketchnote 默认风格与纯文本/可编辑图表分流规则保持不变。

1. **先定语义、再选布局**：一张图只解决一个主要理解问题。对象与能力组成优先用中心辐射/关系图，执行与反馈优先用闭环图，权限、审批及隔离优先用决策/门禁图。相同主题的多张图应在信息问题和关系结构上有差异，不能仅给固定六宫格换配色。图形箭头只表达原文支持的依赖、顺序或条件；不得把并列能力画成必然顺序。
2. **内容证据不随视觉变化**：生成前冻结事实清单、关键限定词、作者归纳与未核实事项。图像模型误做通用宣传图、误写中文或混淆关系时应保留失败证据，按事实清单修复；密集中文可采用可核验的独立排字层，检查准确性和裁切。网页适配不能取代原文事实核验。
3. **原地集成先验身份**：先确认网页 URL 对应的 wiki ID、原始 Org 路径、当前版本与成功的发布绑定；只修改目标文章，不重建新笔记，不更改已有元数据、标题、正文、代码及引用。需要三个不同章节图片时，分别位于文章开头、相应机制章节、相应风险章节；位置由文章语义决定。
4. **附件真实可达**：将图片作为仓库可追溯附件存入原笔记对应的 `note-assets/<WIKI_ID>/`，Org 使用经过路径校验的相对 `[[file:...]]` 链接。WebP 等格式必须先核对当前发布器支持范围。不得把沙箱地址、本地绝对路径或未经发布的资源地址写入 Org。实际资源 URL 由构建输出决定，不能从 Git 源目录直接猜测。
5. **遵守原地更新门禁**：先读取当前发布器关于 `Museum-Update:` 提交、保护头信息、附件、在线核验的约束。本案例的已部署发布器将全文新增的 `#+CAPTION:`、`#+ATTR_HTML:` 也纳入元数据保护；更新既有文章时应优先复用站点已有的响应式图片 CSS 和灯箱，而不是强行新增属性。如果门禁要求每次 `Museum-Update:` 仅修改一篇既有 Org，先独立提交并验证附件，再单独提交 Org。构建被拒绝时保存失败原因，从可核验的干净原文恢复后做最小修复，不绕过校验。
6. **分别验收本地与线上**：至少记录源文件逐字节保真、图片尺寸/裁切/可读性、桌面与手机溢出及点击放大。预览浏览器测试和实际线上截图是不同证据；未实际跑线上浏览器就标记未验。网站发布需检查构建、deploy 的在线验证步骤及与当前 Commit、wiki ID、路径、源内容哈希一致的发布收据；只有收据确认后才称已发布。
