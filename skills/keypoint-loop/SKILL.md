# KeyPoint Loop｜问题关键点复用元 Skill

## 目标
把一次解决问题的过程压缩为下一次能直接使用的关键动作，而不是堆积案例或总结套话。

## 何时使用
- 用户提供问题、处理过程、结果或复盘记录时：提炼可复用关键点。
- 用户提供多条经验时：识别同类，合并重复方法，保留重要差异。
- 用户遇到新问题时：先匹配已有方法；条件不符则不套用。
- 原始材料不足时：明确缺口，允许输出「待验证」，不能补造事实。

## 输入
当前问题及已知事实、采取的行动、观察到的结果；如有，附历史经验卡。
不用要求用户填表。优先从现有上下文提取。

## Loop：捕获 → 逆推 → 归并 → 封装 → 复测

1. **捕获**：明确原问题、卡点、采取的动作、实际结果。找出真正改变判断、决策或结果的证据/动作；没有证据就标记「候选关键点」。
2. **逆推**：从结果倒查：此前缺了什么？新增的哪条信息或动作改变了什么？为何可能有效？还有什么其他解释？删除与成效无明确关系的步骤。不要把先后发生当成因果。
3. **归并**：仅在「底层障碍相同、关键动作相同、适用条件兼容」时合并。相似症状但原因不同，不合并；一个案例只能先形成候选方法。记录来源案例和不能合并的差异。
4. **封装**：把方法写成「遇到【触发条件】→先做【关键动作】→用【证据/指标】验证→若不满足【边界条件】则停止或换路」。保留必要前提、反例和失败信号，不写空泛口号。
5. **复测**：用一个新案例或反例尝试套用。能解释且有效，记「已验证」；尚未测试记「待验证」；出现反证就修订/拆分。无法实际执行时，给出最小验证动作，不声称测试通过。

## 输出（只展示有价值的信息）
**本次突破点**
- 问题/卡点：
- 关键证据或动作：
- 观察到的结果：
- 作用机制：已证实 / 推断 / 未知

**可复用方法卡**
- 名称：
- 适用信号与前提：
- 最小操作：
- 验证标准：
- 不适用/反例：
- 来源案例：
- 状态：待验证 / 已验证 / 有冲突

**归并结果**
- 新增 / 合并入【旧方法】 / 拆分【旧方法】 / 不归档
- 归并依据与重要差异：一句话

## 硬规则
- 事实、推断、未知分开；不编造结果、数字、证据或因果。
- 「做过」不等于「有效」；「结果变好」不等于「该动作导致结果变好」。
- 不为凑分类强行合并；优先合并机制，不按行业名词或表面相似度合并。
- 一条方法卡只解决一个可识别的问题；默认简短，只有关键限制不能删。
- 已有经验库时仅更新新增、修订或冲突的部分，保留来源；没有可访问的持久存储时只输出卡片，不声称已保存。
- 用户没要求完整复盘时，不扩展成报告、不建立评分体系、不添加多余流程。

## 快速调用
「用 KeyPoint Loop 处理以下材料：找出真正有效的突破点，逆向还原原因；与已有经验按同因同法去重合并；输出最短可执行方法卡，并指出尚未验证的部分。」

## 自检
输出前确认：
1. 关键点是否能指向材料中的具体事实或动作？
2. 解释是否把推断伪装成因果？
3. 合并是否满足同因同法，是否保留例外？
4. 下次遇到同类问题，读卡片的人能否立即执行并判断有效性？
任一项失败，降低结论强度或不封装。
