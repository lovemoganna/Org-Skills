# Career Evidence Loop｜从具体工作到通用简历能力

## 目标与边界
简历展示**稳定承担什么问题、如何解决、取得什么可证实的结果**，不把一条 Case 的来龙去脉塞进简历；Case 保留在证据库，供面试时展开。适用各行业；不替代 `keypoint-loop` 的问题关键动作提炼，也不把简历当成项目事故复盘。

## 输入
直接接受流水账、单案、周报、指标、SOP/BRD、岗位 JD 等散乱材料；先用已有信息，不强迫填表。可追加既有能力目录及对应案例证据。没有 JD 时先形成通用能力候选，不能假定具体岗位要求。

## Loop：事实拆分 → 跨案归并 → 能力上抽 → 岗位映射 → 反向验证

1. **事实拆分**：逐项记录问题/背景、本人实际动作、所用证据或方法、可核实结果、时间范围与归属。区分 `观察到 / 可推导 / 假设 / 未知`，尤其区分**个人完成、参与、团队交付、仅了解**。未经证实的数字、因果、上线状态、贡献归属绝不补造。
2. **跨案归并**：先按「解决的共性问题 + 关键决策方法 + 适用前提」聚类，再找不相同的对象、结论和边界。相同风险标签不等于同一能力；同一个 Case 可以支持多个窄能力，但不能单独证明跨领域稳定能力。多案也不自动证明长期掌握：要检查角色、重复性和结果。单案只形成候选描述，除非有可核验的持续职责或其他证据。
3. **能力上抽**：从个案事实 L1 → 可重复方法 L2 → 可迁移岗位能力 L3。**停在最窄但有用的通用层级**：换一位客户、一个币种或同类业务还能成立；换到完全不同领域时须重新证明。用「处理的问题范围 + 核心方法/决策 + 已证实成果或产出」表达，拒绝“优秀、全面、显著提升”等无依据套话。不把一次异常排除写成成功拦截，不把发现风险写成资损挽回。
4. **岗位映射**：面向目标岗位选 3–5 个互不重复的能力主题；按招聘要求调整优先级与术语，但不改写事实。履历主体写长期职责及综合能力；项目经历补独立项目成果；单 Case 主要放面试证据。不要把同一事实在各段重复计数。
5. **反向验证**：对简历每句话追问：①由哪些记录支撑？②谁做的，是否只是团队业绩？③是工作量、方法产出还是业务效果？④换个相似场景是否仍成立？⑤面试能否讲出背景、本人动作、反证、结果及限制？有一项答不上，就缩小、降级或移回案例库。

## 敏锐性门禁（发现问题应主动指出）
- **单案过拟合**：从单一 Case 推出“主导全链路”“全面治理”等，先降为候选，不强行升格。
- **归属偷换**：团队总量/团队挽损 ≠ 个人独立业绩；`参与/协同/负责/主导/上线` 动词按证据选，不用高一级动词。
- **量效混淆**：工单数是规模，SOP/看板是交付，误报下降或挽损是效果；没有前后比较不能写“提升 x%”，也不能把排除误报等同策略优化上线。
- **同词误并**：表面症状相似但机制、处置结果不同，保留分歧；不要把不同场景都包装成同一次成功。
- **抽象过度/不足**：既不能写一条币对调查流水账，也不能只写“具备分析、沟通、管理能力”。优先采用可迁移且能证据回溯的中间表述。
- **隐性边界**：重要的反证、未上线、未证实结果、时间口径、口径重叠应保留在证据库；必要时影响简历措辞。
- **保密**：可公开文本默认不出现客户账号、工单号、私人地址、内部规则阈值或未公开敏感数据。未经用户明确授权，不把内部案例证据发布至公开仓库。

## 默认输出
材料较少时不凑数；优先给出短而有用的三层成果：

1. **简历候选**：1–3 条，每条含能力主题、本人负责范围、方法和有依据的结果（无法量化可写实际交付，不能假造效果）。
2. **证据映射**：各条对应哪些来源 Case/项目、个人贡献级别、证据强度；归并依据和未覆盖的边界。允许写「暂不进入简历」。
3. **面试案例卡**：只选最有辨识度的代表 Case，按问题 → 证据 → 本人判断/行动 → 结果 → 反证/限制展开；不重复写成长篇简历。
4. **关键待核实项**：只列会影响真实性或岗位匹配的缺口；无缺口则省略。

输出时明确区分团队数据与个人数据。未经要求不强制 STAR、大量评分、表单、模板或复杂文件；简历语言自然、精练，面试案例能追溯细节。

## 调用示例
「使用 career-evidence-loop 把以下日常工作记录按事实核验、同类归并、适度抽象、岗位映射和反向验证处理。简历写通用能力，具体案例留作面试证据。不得编造数字或冒领团队成果：<工作记录及目标岗位>」

## 验收与升级
至少跑一个容易误判的原始 Case、一个历史已通过场景、一个机制相反或无业绩的反例；分别检查**误升格、漏关键方法、归属、证据回链、可迁移性、表达质量**。静态格式检查 ≠ 模型按 Skill 执行的效果验证；未做独立调用测试时标注“人工案例走查”，不可声称跨模型或实际招聘效果已证实。
