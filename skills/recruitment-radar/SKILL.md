# Recruitment Radar｜职位增量与失败恢复

## 目标与边界
交付真实且历史未推送的海外交易所交易安全/AML/欺诈风控岗位变化。此 Skill 由 Skill Router V2 按需选择，必须执行真实连接器操作；读文档、生成计划、定时任务 `completed`、工具回执并非验收。没有受信 Work checkout、私有 session、shell 与原生回调时不得声称 `native_legion`，但不得因此中止业务，转为 `direct_fallback` 使用实际可用工具。不得创建替代定时任务。

固定台账 `1861gbbpr23WhS08VM1zZUBusWxUHm3RclVes7tgWXZ8`：
- `岗位主表`：唯一岗位，禁止触碰用户列 S:U（投递优先级、投递状态、备注）
- `核验快照`：独立官方证据的 *实际内容获取日期*、职位ID、申请字段、来源、限制；同公司+ID+获取日期+状态去重
- `变更日志`：只记录实质变化和有证据、已去重的新增；零增量不得写空行

## 执行依赖与退出门禁（不可跳步）

1. **S1 台账基线**：先调用 `get_spreadsheet_metadata`，再有界读取三表所有有效行。记录每个唯一键、requisition 镜像关系、过去来源日期、日志稳定事件键、历史推送和用户列原值。读表失败要尝试有依据的替代访问/精确纠错，但不推断行数。
2. **S2 首个有效子结果**：马上并行请求主表/快照已有的官方 Job ID 独立详情（Greenhouse `/v1/boards/{board}/jobs/{id}?questions=true`，Lever 单职位 API 和独立 Apply）。优先从返回的真实ID/board获取标题、公司、职责、地点、first_published（存在才有）、requisition、questions。官方详情身份一致且有真实申请字段才算申请字段通过。页面获取日期与首次发布日期独立记录。Parallel 缓存不能证明今日开放。若已取得可定位日期的新快照，写前去重、立即保存并回读，不因后续来源受阻丢失产物。
3. **S3 清单与覆盖**：实际向 Parallel `web_fetch` 请求四个完整清单URL：`https://boards-api.greenhouse.io/v1/boards/binance/jobs`、`.../bybit/jobs`、`.../okx/jobs`、`.../bitgo/jobs`。截断/旧缓存时用 TinyFish `fetch_content(ttl=0,include_etag_and_last_modified=true)` 读取相同公开API；对 `text` 仅还原Markdown `\\_` 逃逸后 **严格 JSON.parse**，验证 `jobs.length===meta.total` 且 Job ID 全部唯一；在执行单元内只输出筛选候选，不把巨量原始JSON塞入上下文。ETag 仅作版本指纹，`ttl=0` 不代表已知当天获取日期。清单不可用就改由已知真实ID和独立官网职位继续，不等大型列表成功。按三簇分别搜索交易安全/操纵/策略、AML/制裁/TM/KYB/调查、Fraud/ATO/支付/钱包/账户；覆盖大陆五城和全国远程、香港及新加坡/APAC，优先官方ATS再第三方线索。
4. **S4 BOSS及替代**：分别搜索显性AML/风控、隐性出海/稳定币/钱包/资金安全、招聘主体关联反查。必须打开真实 `/job_detail/` 独立正文，核公司、职责、地点；分类列表不是完整JD。仅返回部分正文标部分，不能计完整独立JD。遇安全页/登录/验证码停止该受限路径，不绕过，实际尝试 Payoneer 官招/Greenhouse 与 Airwallex Careers/Ashby 同UUID页面等合法替代；跨境支付岗位单列，不虚增交易所或BOSS覆盖。
5. **S5 去重与写入**：第一键公司+官方Job ID；同 requisition 地点镜像合并，没有ID时才使用规范职责+地区+剥离tracking参数后的官方URL。`Lever createdAt`、第三方Posted、新发现时间和updated_at均非首次发布日期。只有当前官方可申请证据、未报历史，以及官方首发晚于已有历史截止或官方前后正式快照证明新增，才写主表和稳定事件日志并输出新增。历史覆盖缺口下无法证明新增的职位只存快照作待核线索。变更须有同ID可比前后官方证据，单次404不判关闭。写前重读所有涉及行；写入时禁止修改用户列S:U；日志附稳定键及“已归档，待输出”，不是已送达。写入回执丢失只回读对账，不盲写。
6. **S6 独立验收**：回读实际写入的每张表，验证唯一键、字段、旧→新证据及用户列未改；覆盖核对官方清单成功/不完整数量、独立详情有效数量、内容获取日期、404、BOSS完整独立JD及限制、替代来源、历史去重。未经回读的主表或日志事件禁止输出。无写入明确说“主表未变更”，不称已同步。

## 失败复原（影响业务验收时触发）
以最早失败阶段建一条 **专用元提示**，字段固定为：`failure_id / original_input / observed_receipt / root_cause / revised_action(actual tool and args) / acceptance / fallback / regression_scope`。区分需求误解、工具路由遗漏、解析错误、缓存时效、上游访问限制、权限与验收器错误。必须改变引起失败的参数、工具或来源，在当前轮执行定向复测，再回归原业务链路；同一故障最多两次有新证据的修复，禁止原样重试、测试代替交付或降低新增门槛。复用已经通过的步骤，不因后续阻塞丢弃已回读的快照。

**特别回归样本**：曾有定时轮次只读三表却回报 `completed`，因此“读取三表成功”不得作为结束条件；至少实际核验一项官方独立详情并执行清单尝试。曾有 Parallel 清单摘录截断，改用 TinyFish 后严格解析可用，但这只证明所测原始JSON完整，不证明来源实时或全市场无增量。已知按历史口径复核的旧岗位不能重复通知。Bybit EU API 路径在某读取工具曾返回 `invalid_url`，先核真实官方板块和职位，不凭404推定撤岗。

## 输出
先给北京时间、`native_legion`（必须真实运行轨迹）或 `direct_fallback`、完整/部分/失败、已确认增量。只输出经官方申请证据、历史去重及日志回读通过的新岗位/实质变化，按大陆已确认、疑似大陆、香港/APAC、关闭/变化排序；每项给官方链接及关键限制。没有被证实的增量就只给简明结论和 *实际执行的* 来源质量，不用大量未完成报告或虚假零。宿主有静默机制且无值得通知的新事件时优先静默；不支持时不得声称静默。若存在不可突破的客观阻塞，只报告真实的已尝试、结果、根因、下一步、责任人及既有调度，不编造修复成功。
