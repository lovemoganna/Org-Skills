# Dataset Dashboard Builder

目标：

```text
多表数据 → 数据可信度 → 业务语义 → 分析主题 → 指标 → 变化/异常 → 图表 → 看板 → 质检
```

核心原则：**先决定什么值得看，再决定怎么画。**禁止把字段机械转成图表。

## 1. 扫描数据集

先建立 Dataset Map：

| 表 | 一行代表什么 | 主键/候选键 | 时间字段 | 金额/指标 | 维度 | 可关联字段 |
|---|---|---|---|---|---|---|

同时检查：行数、字段类型、时间范围、NULL、重复键、状态字段、单位、明显异常值。

## 2. Quality Gate

任何 KPI 和图表之前先判断数据能否支持它。

至少检查：

- 主键/候选键是否重复；
- 时间字段是否异常或与业务 ID 冲突；
- JOIN 右表键是否唯一，JOIN 后是否放大；
- 状态口径是否明确，completed / failed / pending 等不得混算；
- 金额单位是否可比较；
- 时间维表（汇率、价格、费率、版本）是否覆盖交易时间。

发现会改变结论的问题时：指标进入 `BLOCKED / LIMITED`，不得静默继续。

## 3. Time-dimension Gate

遇到汇率、价格、费率、版本表，必须先判断：

```text
exact-date / exact-time 是否匹配？
→ 是：按真实时点计算
→ 否：是否有明确 as-of 规则？
  → 是：按 as-of，并说明方向与容忍窗口
  → 否：是否允许 snapshot？
    → 是：指标名称必须写“快照估值 / snapshot valuation”
    → 否：阻断金额换算
```

禁止把单日汇率套到跨期交易后继续命名为“历史成交额”。

## 4. 按业务主题拆分，而不是按表拆分

基于数据自动生成候选主题，只保留有证据且能回答问题的主题，例如：

- 数据可信度；
- 规模与趋势；
- 结构与构成；
- 用户/实体集中度；
- 状态与流程健康度；
- 异常与变化；
- 多表关联与下钻。

一张表可以进入多个主题，多张表可以共同回答一个主题。禁止“一张表一个看板”。

## 5. 指标选择

每个指标必须写清：

```text
业务问题 → 指标 → 粒度 → 分母/口径 → 数据来源 → 限制
```

优先级：

1. 直接回答业务状态的核心 KPI；
2. 解释变化的趋势/结构；
3. 定位问题的异常/Top 对象；
4. 可继续下钻的明细。

同一信息不重复展示。

## 6. Adaptive TopN

Top N 由有效样本数决定：

- active ≤ 10：优先 Top 1 / Top 3；
- 10 < active < 100：Top 5 / Top 10；
- active ≥ 100：Top 10，可增加 Top 1%。

如果 Top N 覆盖全部对象，它不能作为“集中度”核心结论。

## 7. 图表与布局

每张图先写一句：`这张图回答什么问题？`

答不出来就删除。

默认映射：

| 问题 | 优先形式 |
|---|---|
| 当前水平 | KPI / 数字卡 |
| 时间变化 | 折线 / 面积 |
| 类别比较 | 条形图 |
| 构成 | 100% 堆叠 / 环形（类别少时） |
| 集中度 | 排名条形 + 累计占比 |
| 两群体重叠 | 集合数字 / 简洁交叉表 |
| 异常对象 | 排名表 / 明细表 |
| 数据质量 | 审计表 |

禁止为视觉丰富度凑图、重复 KPI、滥用饼图或用装饰卡片替代分析。

## 8. 页面层级

默认阅读顺序：

```text
关键结论/限制
→ 核心 KPI
→ 变化与结构
→ 异常/集中度
→ 下钻明细
→ 数据质量与口径
```

如果数据质量问题会改变核心数字，限制必须靠近 KPI，不得藏在页尾。

## 9. 数据刷新

数据更新后：

1. 重新扫描 Schema 与质量；
2. 重算主题和指标；
3. 仅在证据变化时新增/删除图表；
4. 不把旧数据集的字段、指标、图表写死到新数据集。

验收：换成结构明显不同的数据集，仍应重新理解并生成不同看板。

## 10. HTML / Dashboard 输出

需要 HTML 时：

- 使用真实计算结果，不在 Renderer 中重新推导数字；
- 核心指标、口径和来源可追溯；
- 桌面与移动端均不得整页横向溢出；
- 长表局部滚动；
- 交互必须有明确作用，不为“像产品”增加无意义控件；
- 不依赖外部库也应保留可读 fallback（如果成品要求离线可用）。

生成后必须执行 `references/regression-loop.md`。

## 11. 停止条件

只有同时满足才完成：

- 无已知 P0/P1 数据逻辑问题；
- 每个核心图表都回答明确问题；
- 关键指标口径可追溯；
- 无重复/装饰性图表；
- Rendered QA 通过；
- 新发现的可泛化缺陷已回写 Skill 并复测。
