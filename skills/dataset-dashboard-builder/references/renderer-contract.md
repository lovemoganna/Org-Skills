# Renderer Contract

目标：把“分析语义”与“具体图表库”彻底分开。Renderer 只负责把已验证 Result 画出来，不负责重新理解字段、改口径或查询数据。

唯一允许的链路：

```text
Semantic Field Catalog
→ Analysis Intent
→ Analysis Spec
→ DuckDB SQL
→ Result Contract
→ Visual Spec
→ Renderer Adapter
→ UI
```

## 1. Renderer Ownership

Renderer Adapter 只能消费：

- Analysis Spec；
- Result Contract；
- Visual Spec；
- Theme / locale / interaction state。

Renderer Adapter 禁止：

- 直接访问 DuckDB；
- 自己拼 SQL；
- 改 aggregation；
- 改 time grain；
- 改 TopN；
- 重算 rate / percentage；
- 把 identifier 当 measure；
- 因库的能力限制改变分析问题。

如果 Renderer 无法忠实表达 Visual Spec：

```text
补插件 / 自定义实现
→ 同语义等价形式
→ table / native fallback
```

禁止随机换图。

## 2. Renderer Selection

按分析意图和交互需求选 Renderer，不按“当前库有什么图”反推分析。

### Vela

适合：

- 金融 / 资金类时间序列；
- amount / count / price / balance 等随时间变化；
- 需要 zoom / pan / crosshair / range preset；
- 多图时间轴或 crosshair 同步。

规则：

- 优先使用离线 `data` 注入已计算好的 bars；不得默认接 Binance / Coinbase 等外部行情；
- Vela 只消费 Result，不参与业务聚合；
- 聚合型业务时间序列使用 line / area 语义，不得伪装成真实 OHLC K 线；
- 如果适配层必须将单值时间点映射到 OHLCV 传输结构，`open=high=low=close=value` 只是 renderer transport，不得在 UI 称为 K 线；
- 主图必须保留用户要求的 zoom / pan / crosshair / range selection；
- 多图共享同一时间域时，应同步 crosshair；
- WebGL2 不可用时允许使用库自身 Canvas2D fallback；
- 如果用户明确要求离线成品，必须打包本地 bundle 或提供无库可读 fallback；
- Vela API 仍在演进，成品必须 pin 到已验证的明确版本 / revision，不引用无版本 `latest`；
- 保留 Vela 默认可见 attribution；若关闭内置 attribution，必须在同一页面提供等价、可见的 Vela™ 项目归属。

### Chart.js

适合：

- generic category comparison；
- composition；
- distribution；
- scatter / relationship；
- 简单非金融 trend。

Chart.js 是可选 Adapter，不再是整个 Skill 的唯一默认 Renderer。

### Native HTML / CSS

优先用于：

- KPI；
- compact status structure；
- sortable detail table；
- evidence queue；
- 少量实体排名；
- 图表库不能增加信息、只会增加噪声的简单结构。

## 3. Visual Spec

Visual Spec 至少包含：

```text
spec_id
intent
renderer_family
chart_family
x
y
series
time_grain
sort
top_n
unit
formatter
label_policy
interaction_policy
theme_policy
locale
```

Renderer 不得重新猜这些字段。

## 4. Label Policy

如果用户要求图上永久显示值，视为硬约束。

默认：

- vertical bar → label 在柱顶外侧；
- horizontal bar → label 在柱尾外侧；
- point / line → label 在点位上方；
- stacked segment → 仅在空间足够时放内部，否则外置或改为上方 summary；
- label 必须避让、不得与 mark / axis / legend 重叠；
- 必须预留 top / right padding，避免裁切；
- tooltip 不能替代用户明确要求的 permanent label。

高密度时间序列如果“每点都显示”会破坏可读性：

- 使用 renderer overlay / selected-point label / synchronized readout；
- 同时保留完整数值在 table / data window；
- 若用户明确要求所有点永久显示，则必须实现碰撞策略，不能静默省略。

## 5. Interaction Contract

所有交互必须发出语义事件，例如：

```json
{"spec_id":"funds_amount_trend","dimension":"time_bucket","value":"2026-01"}
```

Controller 负责：

```text
Interaction Event
→ Global Filter State
→ patch Analysis Spec
→ recompile SQL
→ Result
→ Visual Spec
→ rerender
```

要求：

- 点击同一筛选值可取消；
- selected / hover / focus 必须有可见状态；
- Chart 与 Table 的选择状态必须一致；
- 多图时间序列可同步 crosshair，但 crosshair 本身不自动改变过滤范围；
- Filter 不能在组件内部维护一份独立数据副本。

## 6. Language & UI Copy

最终 Dashboard 的主要语言跟随用户语言。

中文任务默认：

- 标题、筛选、状态、提示、表格列名、下钻内容使用中文；
- ACH / USDT / Tx Hash / UID 等必要业务术语可保留；
- 不把 Analysis Spec、Compiler、Regression、Generated by 等开发术语暴露给业务用户；
- 删除重复说明、教程式废话和“为了显得专业”的说明文本。

## 7. Theme & Component Consistency

浅色 / 深色必须共享同一组件状态模型：

`default / hover / focus / selected / disabled / empty / loading / error`

统一：

- font scale；
- spacing；
- border；
- radius；
- panel background；
- control height；
- selected state；
- table hover；
- empty state。

Renderer 的 theme 必须从全局 tokens 映射，不允许局部自成一套。

## 8. Acceptance

必须同时满足：

- Result 与图上值一致；
- Renderer 未重新计算业务口径；
- 时间序列首尾日期可见；
- 交互筛选能回写 Global Filter State；
- 标签无遮挡 / 不裁切；
- 深浅主题一致；
- 移动端不整页横向溢出；
- Renderer 不支持时有等语义 fallback。
