# Dashboard Regression Loop

## 1. 基线

先保存输入、指标口径和当前可运行 HTML。修正只针对已复现缺陷。

## 2. 缺陷分类

- P0：数字错误、口径错误、JOIN 放大、历史/快照混淆、核心功能不可用；
- P1：主问题漏答、关键限制隐藏、错误 TopN、移动端破版；
- P2：明显可读性问题；
- P3：纯审美，不主动修改。

## 3. 每轮闭环

```text
真实执行
→ 定位缺陷
→ 判断是否属于 Skill 规则缺失
→ 最小修正
→ 原失败样本复测
→ 泛化测试
→ 历史回归
→ Diff 检查
```

## 4. Rendered QA

至少检查：

1. 核心 KPI 与分析结果一致；
2. 关键限制与受影响指标相邻；
3. DOM 关键区块存在且非空；
4. JS 语法无错误；
5. ID 唯一；
6. 桌面/移动端无整页溢出；
7. 表格可局部滚动；
8. 无重复 KPI / 图表；
9. 每张图能回答明确业务问题；
10. HTML 离线打开时核心内容仍可读。

## 5. 泛化测试

至少覆盖：

- 无时间维表的数据集；
- 多日期汇率/价格表；
- 小样本 active ≤ 10；
- 一对多 JOIN；
- 没有金额字段、只有事件计数的数据集；
- 完全不同字段名的数据集。

不得因为某个真实样本出现 `users / fiat / crypto / exchange_rates` 就把这些名字写成通用规则。

## 6. 停止条件

原样本、泛化、历史回归全部通过；继续修改只剩审美偏好时停止。
