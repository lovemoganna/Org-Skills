# Analysis Depth Protocol

目标：避免“扫表 → 算总量 → TopN → 画图”这种浅层看板。分析必须从数据结构逐步推进到能改变判断的关系、差异和驱动。

## 1. 先生成 Question Map

完成 Dataset Map 与 Quality Gate 后，先列候选问题，不直接画图：

| 分析问题 | 决策价值 | 数据是否支撑 | 粒度 | 比较基线 | 方法 | 候选可视化 |
|---|---|---|---|---|---|---|

候选问题来自真实字段、表关系和业务对象，不从固定模板硬套。

## 2. Analysis Depth Ladder

按数据实际支持程度逐层推进：

### L0 · 数据可信度

检查粒度、覆盖、NULL、重复、时间连续性、状态口径、JOIN、单位、异常值。

### L1 · 基线

回答“有多少 / 多大 / 当前是什么状态”：

- 总量、笔数、活跃对象；
- 成功率、失败率、均值/中位数；
- 关键比例与分母。

L1 只能建立基线，不能单独构成“深度分析完成”。

### L2 · 分布与分层

回答“差异藏在哪里”：

- 数值分布、长尾、极端值；
- 用户/实体分层；
- 类别、地区、渠道、状态、产品等分组；
- 同时看绝对量与标准化指标，避免“大组天然更大”。

能算比例时必须保留分母 N。

### L3 · 时间与变化

回答“什么时候发生变化”：

- 趋势、周期、峰谷；
- 环比/同比/前后期；
- 新增、消失、迁移；
- 数据足够时检查季节性和结构漂移。

时间点太少时，不得伪造连续趋势。

### L4 · 关系、流程与跨表

回答“对象之间怎么连、在哪一步发生损耗”：

- 多表交叉关系；
- 生命周期、状态迁移；
- 漏斗/阶段转化；
- cohort / retention；
- 来源 → 中间状态 → 去向；
- 两个数值变量关系；
- 实体与渠道/产品/资产之间的组合模式。

只有数据中存在对应路径、阶段或关系时才生成。

### L5 · 驱动、集中度与异常

回答“为什么值得关注”：

- Top1 / TopN / 累计贡献 / HHI 等集中度；
- 变化贡献拆解；
- 高影响维度和异常对象；
- 失败、延迟、费率、转化等效率差异；
- 交叉分层后的反常组合。

相关不等于因果。没有实验或因果设计时，只能写“关联 / 贡献 / 同期变化”。

### L6 · 决策与行动入口

回答“看完下一步做什么”：

- 哪些对象值得优先下钻；
- 哪个维度最能解释差异；
- 哪项数据缺口最影响判断；
- 哪个异常需要人工核查；
- 哪个指标应进入持续监控。

不凭空给业务建议；行动必须能回指数据证据。

## 3. 深度门

只要数据支持，就不得停在 L1。

默认至少完成：

```text
L0 数据可信度
→ L1 基线
→ L2 分布/分层
→ 再从 L3/L4/L5 中至少选择一个真正有证据的高价值方向
```

如果只能做到 L1，必须说明是数据限制，而不是把浅分析包装成完整看板。

## 4. 问题优先级

候选分析按四项排序：

1. 是否会改变用户对数据的判断；
2. 是否能定位具体对象/维度；
3. 是否有可靠证据和可解释口径；
4. 是否与已有图表提供不同信息。

低价值重复切片删除，不以“图越多越好”为目标。

## 5. 深度分析常见方法

按问题选择，不机械全跑：

- 分布：P50 / P90 / P95、IQR、长尾、零值；
- 标准化：人均、每笔、每活跃对象、成功率、占比；
- 集中度：Top1 / Top3 / TopN、累计占比、HHI；
- 流程：成功率、阶段转化、完成时延、失败/取消分布；
- 交叉分析：维度 × 状态、维度 × 时间、维度 × 指标；
- 贡献：变化量按维度拆解；
- 关系：相关、散点、组合矩阵；
- cohort：首次时间 × 后续行为；
- 异常：时间异常、结构异常、实体异常、规则冲突。

样本太小时，优先展示原始 N 与描述性差异，不制造统计显著性。

## 6. 分析输出契约

进入可视化前至少保留：

```text
Question Map
→ 关键口径
→ 分析结果
→ 哪些结果改变判断
→ 哪些结果只适合作为下钻
→ Visual Plan
```

图表是分析结果的表达层，不能代替分析过程。
