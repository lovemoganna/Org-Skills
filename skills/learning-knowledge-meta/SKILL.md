# Learning Knowledge Meta｜从课程材料到长期知识资产

## 目标与边界

输入可以是单节/多节字幕（SRT/VTT/文本）、讲义、代码、练习、页面或课程目录。输出是能回答真实问题、追溯重要来源、支持实际操作的知识笔记，而不是字幕压缩版。**只依据实际可读取的材料工作**；不能因为课程名称、视频标题或预期大纲，就声称读过不存在的章节。

默认中文写作，必要专业术语保留英文；按用户明确的语言、目标知识库和发布要求调整。没有发布要求时仅交付笔记，不触发远程写入。纯翻译用翻译工具；已有笔记的独立重写交由 `note-reforge`；百科查询和与课程无关的研究不在本 Skill 范围内。

此 Skill 只管理**学习材料特有的来源、知识建模、跨课时整合与验收**。不重新实现 Org 存储、Git 操作、发布、已存在知识库维护、通用 Loop 或代码执行器。

## 执行

1. **界定输入。** 确认材料实际可读，记录可得到的课程/课时名称、来源 URL、文件标识、版本或内容哈希、字幕时间段及已处理范围；缺少即写未知。对多文件建立处理清单、主题关系和重复检测键（已有稳定标识优先，内容哈希可得时辅助）；断点续做只处理未完成范围。不能用文件数量或标题推断整门课程已覆盖。
2. **复原知识。** 阅读内容，确定学习者实际需要解决的问题；提取概念与定义、机制、成立条件、推导、重要限定、案例和反例、实验数值、公式、代码、练习及可执行步骤。跳过广告、口头重复和无信息过渡，但不能因为篇幅压缩而删掉改变结论的条件或反证。语音识别歧义、字幕截断和讲者错误须分别标注，不能把推测填回课程事实。
3. **建立证据关系。** 对关键定义、独有观点、公式、代码、数值和可争议断言，尽量保留可定位的课时/时间码/页码/代码位置；确实没有定位信息则标注定位缺失。区分 `课程内容`、`〔补〕独立补充`、`待核实`、`真实执行结果`。补充外部知识必须解决具体理解或应用缺口，并有可核实的来源或明确的推断边界。不要逐句堆时间码；每个影响判断的关键主张必须能反查。
4. **组织知识。** 根据以后会问的实际问题来安排标题和层次；可采用“问题—机制—使用条件—操作—反例/失效边界”。短题不制造章节，复杂题保留必要推导。对于多个课时，先分别处理，再合并真正重复的结论；前置依赖、相互矛盾、版本漂移及不同方法的适用条件要保留。处理范围未齐全时只交付当前范围，不做冒充全课的全局归纳。
5. **实践分流。** 教程含代码/命令时，保留原始可复用片段及运行条件；需要将技术教程转为可参数化的 Org/Babel 时调用 `org-literate-engineering`，而不是只因为有几行示例代码就强制执行。破坏性、付费、外部写入或凭据相关操作未经授权不执行。分别记录静态检查、隔离运行、目标环境实测、未验证；禁止把示例输出或预期效果冒充 `#+RESULTS:` 实测。
6. **知识库分流。** 先查已有相关笔记：同一问题优先增量整合，独立问题新建，有明确分工的系列保留边界。已有已发布笔记不得因相似标题而覆盖。目标是 Org Notes 时，依据仓库当前规范，原料尚不是笔记时先形成忠实草稿，再按需使用 `note-reforge`（已有笔记或草稿的内容加工）、`llm-wiki-maintainer`（跨页关系/已有知识增量）与 `org-museum-ingest`（公开收录/提交/发布）。子 Skill 的职责、权限与存储规则以读取到的**当前真实版本**为准；不可访问时报告缺口，不猜路径、ID 或最终 URL。其他知识库只按其真实适配器处理，不假定具备 Org Notes 的接口。
7. **公开与版权门禁。** 使用独立表述的知识解释，保留必要短引用及来源，不大量复刻受版权或许可限制的字幕、讲义、原始课程代码或课件；注明来源不等于获得转载许可。除非明确允许，不发布原始字幕、课程视频、讲义、私人学习记录、账号信息、密钥或受限附件。无法安全公开时交付私用笔记或阻止发布，不以“用户要求自动发布”覆盖限制。
8. **验收再发布。** 对照实际输入反查关键论断、边界、数字与代码；检查实用性（读者是否能据此解决原课程教的问题）、缺失范围、冲突、Org 结构/链接、补充标记和公开风险。**结构测试通过不等于内容正确**；没有独立语义评审时不得说“已独立验证全部知识”。只有用户授权发布且前述关键门禁无阻塞时，才调用目标知识库的写入与发布流程；提交、CI 成功、部署成功、页面内容版本已核验是不同状态。核对 Commit、发布记录及实际页面；不能虚报。失败时保存经过检查的 Org 候选和可恢复的范围状态，不让生成成果随发布失败丢失。

## 最小状态与证据契约

按任务复杂度保留一份**工作记录**（不要把流程台账塞进公开笔记）：

- `sources`：输入标识、类型、实际来源、可得版本/哈希、课时与定位方式、是否可公开。
- `coverage`：实际读过的章节/时间区间、未处理区间、冲突与歧义。
- `claims`：仅对关键主张记录文本、来源位置、性质（原文/〔补〕/推断/待核实）与证据强弱。
- `artifacts`：候选笔记、更新或新增决定、必要的关联与原始内容保护情况。
- `execution`：代码/实验检查的真实类型与结果，未运行直接写未验证。
- `publication`：未请求/待提交/已提交/部署中/页面已核验/阻塞；已知时关联真实 Commit 与页面核验回执。

简单单节可将状态压缩在内部；分批任务须保留可继续执行的处理清单。重复输入且无新知识时应输出 `NOOP`，不得为了有提交而创建重复页面。来源更新或笔记内容改变时只更新受影响的主张与页面，保留既有身份与未受影响内容。

## Loop 质量门禁

需要质检/改进本 Skill 时读取远程当前 `skills/loop-engineering-meta/SKILL.md`，按其 G0–G6 做**范围适配 → 真实样本 → 证据与成果审查 → 反例/回归 → 最小修复**。先生产可检验的笔记候选，再审查；不把评审报告当知识产物。至少覆盖：真实单节字幕、含代码教程、多节不完整或冲突材料，以及未授权/无发布回执的失败路径。结构、证据、语义可用性和发布结果分开判定；自评、模拟与静态检查不能冒充独立端到端验收。没有独立实测时保持 `CONDITIONAL PASS`，不据此覆盖稳定生产版本。

## 结果

用户要求发布：只给候选/已发布笔记链接、真实 Commit/PR、准确发布状态、影响使用的缺口或未验证项。未要求发布：交付完整笔记或文件与必要来源缺口。发生阻塞时交付可恢复的成果和明确阻塞环节；不输出工具流水账、空泛自评或重复摘要。

最短调用：`用 learning-knowledge-meta 炼化并发布这些课程材料：<文件/URL>`；仅炼化：`用 learning-knowledge-meta 整理这些课程材料，不发布：<材料>`。
