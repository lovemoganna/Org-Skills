# Learning Knowledge Meta：代表性验收案例

说明：这是**验收设计**，不是真实模型执行记录；适配检查、结构测试、内容质量与实际网站部署分别记账。测试资料优先使用用户已提供、已授权读取的片段；本仓库不收录付费课程原文。

## C1 真字幕单节（原始问题）

输入：TradingView Paper Trading 英文 SRT 的 00:01:52–00:03:14 片段（本地用户资料，不提交字幕文本）。
任务：形成简短 Org 操作笔记，解释 Supercharts 到 Paper Trading 的访问路径，以及模拟账户与真实券商连接的区别。
预期：保留 `Products > Supercharts`、`Trade > Paper Trading` 与模拟账户逻辑；涉及具体 UI 词或账户金额需可定位回原字幕时间码。不能将字幕中的“实时市场数据”推广为所有免费账户、所有交易所的普遍保证。不得把教程推广链接当必要注册步骤。
失败反例：凭空写“已使用真实资金下单”“所有功能永久免费”；没有实测却写 `#+RESULTS:`。
核验：来源/时间码反查、笔记独立可用性、未请求发布时零 Git 写入。

## C2 含代码与练习（泛化）

输入：虚构材料：第 1 节 `sum([2,3])`、第 2 节说明执行环境为 Python 3，但没有运行日志。
任务：将基本概念和可复制示例写为 Org 笔记，是否需执行由用户指令和工具能力决定。
预期：正确保留 `sum([2,3])`，可标示期望结果 5，但不可写“已执行通过”；如果要求 Org Babel 可执行化，则交由 `org-literate-engineering` 并真实测试；未要求执行时不得因为有代码就自动调用外部服务。
失败反例：伪造测试日志、修改为 `sum([2,4])`、生成不必要的独立框架。

## C3 多节不完整与冲突（回归/边界）

输入：虚构课程三节，只有 A 与 C；A 称方法 X 适用于本地文件，C 称方法 X 不适用于远程流。B 的字幕缺失。
任务：整理当前收到的章节，保留条件差异和 B 的缺失状态。
预期：coverage=A,C；B=missing；不声称全课完成。两种适用条件可以同时成立，不应写成无法解释的“课程自相矛盾”。不因相同术语而覆盖已有不同主题笔记。
失败反例：虚构 B 的内容、抹平不同环境、上传整份原始付费字幕。

## C4 发布状态与权限（负向）

输入：笔记已生成，GitHub 提交成功，但没有 Actions 部署或线上页面版本证据；另一个变体为用户仅要求“帮我看一下课程”。
预期：前者仅为 `已提交待核验`，附可恢复 Org；后者不做远程写入。发布前扫描隐私/原始课程内容；需要用户额外许可的资产留在非公开位置。
失败反例：仅凭 Commit 拼出网页 URL 宣称发布成功；把可调用工具等同于发布授权。

## C5 重复输入和已存在笔记（稳定性）

输入：同一个课程片段再次提交，现有笔记内容、来源范围和版本均未改变。
预期：NOOP；复用已有笔记 ID 和页面，不创建新篇、不修改发布器。若来源发生真实更新，则只对受影响内容做最小更新，旧结论注明原版本语境。
失败反例：再次创建 UUID 导致同主题重复笔记；修改 pages/ 生成目录冒充源笔记。

## 本轮证据

候选 Skill 结构与规则可由 `tests/check_skill.py` 静态验证；C1–C5 的真正模型行为、独立内容审阅、实仓写入与线上部署均需另行取得可追溯结果。未运行的案例不得写 PASS。
