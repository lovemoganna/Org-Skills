# 默认 Markdown 分析教程交付契约

报告按**读者理解顺序**组织，而非把后台 Gate 和中间表作为前台章节标题。

1. **任务模式与一句话结论**：说明本轮解决什么、已确认哪些事实；未运行则直说，不放假结论。
2. **数据集概览**：四表的实际规模、字段与关系，来源和执行环境。
3. **质量与边界**：重点缺陷与 BLOCK / SCOPE / WARN 的实际影响。
4. **候选问题池**：问题、类型、Hard Gate、入选/淘汰的可核查理由。只罗列有区分度的候选，不抄全部字段。
5. **入选问题（通常 2–4 个）**：按发现脉络逐项呈现：
   - 当前问题与为什么先做；
   - 已知事实 vs 分析口径，指标语义与数据范围；
   - 主 DuckDB SQL（格式化且完整）；
   - 实际结果（只来自查询）；
   - Validation SQL + PASS/BLOCK/SCOPE/WARN；
   - 结果解释、局限、下一问题为何成立或为何停止。
6. **SQL 学习地图**：把这次实际用到的 SQL 操作与触发的真实问题对应起来，不反向补齐所有语法。
7. **未选问题与停止理由**：注明数据不足、语义不明、重复、低优先级或需要进一步证据。
8. **附录：复现与审计**：原始四表读取 SQL、Schema、完整 SQL 和查询结果/验证日志；如无法运行要附确切环境阻塞和已完成边界。

格式：中文直接陈述；SQL 使用 `sql` fenced code block，保留换行、缩进、缩写展开，避免省略号替代关键逻辑。关键数字附查询来源、单位和分母。不要把推断写成因果。仅在用户明确要求时另外生成 HTML。
