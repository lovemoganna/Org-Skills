# DuckDB SQL 数据驱动 SOP

## 定位与边界

把真实数据当作分析对象和教学载体。先观察事实，后提出问题，按需增加 SQL 能力；不按语法目录编排课程，不预设业务结论，不为讲解 `JOIN` 或窗口函数制造问题。

这是 **SOP V2.2 的 Skill 封装**，不是对 SOP 的未经授权修订。与已有 `sql-business-thinking` 的职责边界：本 Skill 负责**本数据集的教学型问题路由、证据分层、按需分析与停止判断**；不要自动调用其他 Skill 改写步骤。收到审计请求时只诊断，不自行修复。

默认任务绑定一份真实工作簿，强制只读四张允许表。执行前阅读 [数据契约](references/dataset-contract.md)；要换数据集或允许表，须有用户明确授权，不能推断放宽白名单。

## 执行要求

1. **确认任务模式**：教学驱动、业务驱动、混合。没有明确业务决策时用教学驱动；只有用户同时提出真实业务分析和教学训练时才用混合模式。不能虚构业务目标。
2. **验证环境**：检查 DuckDB 引擎、Excel 扩展、真实 XLSX 可达性与白名单读取路径。允许 CLI、Python、Web Shell、WASM；**正式业务计算只能由 DuckDB SQL 完成**。不要把环境检查扩成无止境的排障；失败时保留证据并标明未执行。
3. **Phase 0：原始勘察**。仅检查列名、DuckDB 推断类型、行数、时间范围、NULL、重复、关键标识唯一性、类别取值、潜在关联键和关联覆盖率。记录已确认事实、未知及异常等级。此时不决定最终指标、排名、趋势或 SQL 课程章节。
4. **规范化业务键**：在 JOIN 前检查两侧类型和业务含义，选定 canonical type，显式 `CAST`/`TRY_CAST`，验证转换失败、转换后唯一性、关联覆盖。ID 优先视为标识，不依赖隐式类型转换。
5. **Phase 1：生成候选问题**。只根据真实字段、真实取值、实际关系、质量现状及用户目标提出问题。**先生成问题，后按需构造交易事实层**。区分描述型、比较型、推断型；描述当前样本不因样本小自动淘汰，外推需要额外证据。
6. **Hard Gate**：淘汰数据不能回答、指标不清、无法验证、明显重复、无法控制重复计量、依赖禁止表或未知业务规则、纯粹为了覆盖语法的问题。不要因为 SQL 简单、仅用 `GROUP BY` 就淘汰真正的教学问题。
7. **Routing Budget**：通常选 2–4 个最有分析或教学价值的问题；合格不足则少做。教学模式比较信息增量、教学增量、数据支持度、可验证性、思维递进、非重复性与复杂度；业务模式只在明确业务目标时比较决策价值。评分不能假装有 SOP 未定义的统一数字公式。详见 [问题路由](references/routing-and-teaching.md)。
8. **Phase 2：按问题建数据需求**。仅为入选问题确定原始表、筛选总体、粒度、JOIN、币种统一、时间和用户全集；需要时用 CTE、VIEW 或 TEMP TABLE。单次使用倾向 CTE，多下游复用或独立验证可物化；不能为阶段形式机械建表。
9. **指标 Gate**：明确对象、总体、时间、粒度、单位、分子、分母、正负方向、去重、NULL、可比性与可加性。**同单位不等于可以跨经济事件相加**；`net = 0` 不等于无活动。观察事实、口径决定、推导、正式结论必须分别标明。
10. **执行分析闭环**：对每个入选问题先给动机和指标定义，执行最小必要 DuckDB SQL，展示真实结果；再执行独立 Validation SQL，对账并标出 PASS、BLOCK、SCOPE 或 WARN，形成新事实。未验证不输出确定性结论。
11. **重新路由与停止**：每轮根据结果重新比较问题池，可分叉、回退或停止；若后续问题只是重复发现、无法被当前数据支撑或仅为了覆盖 SQL 语法，停止该路径。不要预设下一课一定讲窗口函数。
12. **报告交付**：默认输出中文 Markdown 教程，正文先结论、再数据和真实问题，SQL 全文及审计证据置于后部；SQL 使用规范缩进与语法代码块。使用 [报告模板](references/report-format.md)。只有用户明确要求才添加网页等展示层。

## 不可越过的门槛

- **数据源**：只读取 `users`、`fiat_transactions`、`crypto_transactions`、`exchange_rates`；不得读取工作簿的其他表来获得字段规则、答案或线索。
- **SQL 真执行**：页面预计算、Pandas/JavaScript 业务计算、猜测结果与 SQL 运行结果不可混称。没有 DuckDB 的真实查询日志就报告“未完成 DuckDB 执行”。
- **语义**：fiat/crypto 即便都折成 USDT，也不得未经经济事件去重/可加性证明就强行算总净流入；基准汇率不得称作交易当时的成交估值。
- **异常分级**：BLOCK 停当前不可信路径，SCOPE 仅阻断受影响的问题，WARN 保留限制继续；不要因一个字段问题停止整个分析。
- **输出证据**：每个关键结果都须关联来源表、字段、SQL、实际结果、Validation、结论适用范围。

完整异常与指标说明见 [执行及验证规则](references/execution-and-validation.md)。本 Skill 仍有 V2.2 已知未决点，执行/测试时阅读 [已知限制](references/known-limitations.md)，不得宣称它们已修复。

## 最小交付清单

交付应包含任务模式、数据源约束、数据质量事实、候选问题选择与排除依据、入选问题逐项 SQL 与结果、独立验证、SQL 学习地图、停止理由和未证实事项。正文服务于初学者理解“为什么现在用这条 SQL”，审计细节服务资深分析师复核。

如用户要求**审计 SOP 本身**，依照真实执行记录指出卡住的具体步骤与证据，不擅自修改 SOP；说明实际执行状态与剩余缺口。

## 维护与验收

修改前保存版本和行为基线；针对真实、边界、失败、误触发测试做回归；只修已证实的问题，禁止通过删规则掩盖失败。测试用例在 `evals/evals.json`，本地**结构性校验**运行 `python scripts/validate_skill.py`。该校验不能替代 Claude 的触发测试或真实 DuckDB SQL 回归。
